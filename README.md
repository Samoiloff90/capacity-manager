# Capacity Manager

Локальное desktop-приложение для квартального планирования capacity команды.
Одна команда — отдельная папка с SQLite; расчёты выполняются на компьютере,
проекты хранятся локально. Стек: Tauri 2, React 18, TypeScript и SQLite.

## Текущая готовность

- Подключён сценарий создания, открытия и закрытия проекта в выбранной папке.
  Данные хранятся в `capacity.sqlite`; название команды можно изменить в интерфейсе.
- Можно создавать и выбирать кварталы, редактировать сотрудников, компетенции,
  ставки, календарь, отсутствия и доли направлений. Доступны своды часов по людям,
  компетенциям и направлениям, сохранение и повторное открытие плана.
- Встроен календарь РФ на 2026 и 2027 годы. Для другого года требуется явно подтвердить
  ручную проверку пятидневки, праздников и переносов. Поправки сохраняются в квартале.
- При несохранённых изменениях смена плана или закрытие требуют выбора пользователя.
  Сумма долей, отличная от 100%, показана предупреждением; такой план можно сохранить
  как черновик.
- Во вкладке «Задачи» можно добавлять и редактировать название, направление и оценку
  в часах, переносить задачи между направлениями и удалять с подтверждением.
  Свод показывает потребность, остаток или дефицит; пустые оценки отмечаются отдельно.
- Сохранённый квартал выгружается в отчёт Excel (XLSX) кнопкой **«Выгрузить отчёт»**.
- Сборки для Mac (Apple Silicon) и Windows x64 публикуются как релизы на GitHub.
- Импорт ещё не реализован; проверка на Mac пользователя ещё не выполнена.

DEC-023: фоновые обращения системного движка (WebView2, WebKit) допустимы, но
приложение не должно передавать данные команды. Проверка сети версии 0.1.0:
- **Windows:** маркеры данных команды в трафике не найдены. Одно соединение движка с
  сервером Microsoft идёт вне NetLog, его содержимое не проверено.
- **Mac:** проверены только запуск и выход на сервере GitHub. Пока сценарий с данными на
  Mac не проверен, работайте там с учебными данными.

Методика и результаты — [NETWORK_CHECK.md](docs/audit/NETWORK_CHECK.md), прошлая
проверка до DEC-023 — [WINDOWS_PORTABLE.md](docs/audit/WINDOWS_PORTABLE.md).
Целевые ОС — Windows 10/11 x64 и macOS arm64. На Mac пользователя приложение ещё не
проверялось — чек-лист в [MACOS_BUILD.md](docs/audit/MACOS_BUILD.md).

Старый код и его тесты сохранены, но основной запуск больше не открывает прежнюю
`capacity.db`, не запускает её миграции и не переносит данные автоматически.

В новой модели распределяются **все доступные часы**; встречи — отдельное направление.
Например, 20% от 100 доступных часов дают 20 часов, без предварительного вычета 30%.

## Скачать

Готовые сборки — на странице
[Releases](https://github.com/Samoiloff90/capacity-manager/releases). Вход в GitHub не
нужен. Пробные версии (0.x) помечены **Pre-release**. Файлы — в разделе **Assets**
нужного релиза:

| Компьютер | Файл |
| --- | --- |
| Mac на Apple Silicon (M1 и новее) | `Capacity-Planner-<версия>-macos-arm64.zip` |
| Windows 10/11 x64 | `Capacity-Planner-<версия>-windows-x64-system-webview2.zip` |

Рядом лежат `.sha256` с контрольными суммами. Они же указаны в описании релиза.
«Source code» для запуска не нужен. Установщик, права администратора, Rust и Node не
нужны.

**Где хранить данные.** Каждая команда — отдельная папка с `capacity.sqlite`. Не выбирайте
папку внутри OneDrive или iCloud Drive: часто синхронизируются «Документы» и «Рабочий
стол», и их содержимое выгружает в облако сама система, а не приложение. Подойдёт,
например, `~/Capacity` на Mac или `%USERPROFILE%\Capacity` на Windows.

## Запустить на Windows

1. Распакуйте ZIP целиком в отдельную локальную папку и прочитайте `README-PORTABLE.txt`.
2. Запустите `capacity-planner.exe` без прав администратора.
   **Нужен уже установленный WebView2 Evergreen; в ZIP он не включён.**
3. Сборка неподписанная. Если SmartScreen покажет «Система Windows защитила ваш
   компьютер» — «Подробнее» → «Выполнить в любом случае». Делайте так, только если
   SHA-256 архива совпадает с описанием релиза (`Get-FileHash <путь к zip>` в PowerShell).
   Если политика организации не даёт такой кнопки, не обходите её.

Запуск на чистой корпоративной Windows без администратора и на Windows 10 ещё не
подтверждён. На текущей Windows 11 EXE запускается с обычными правами пользователя.

Локальная сборка разработчика — `src-tauri/target/release/capacity-planner.exe`,
см. «Проверки и сборка». Перед пересборкой закройте запущенное приложение.

## Запустить на Mac

Сборка — только для Mac на Apple Silicon (M1 и новее). Установщик, права администратора и
Xcode не нужны.

1. Скачайте `Capacity-Planner-<версия>-macos-arm64.zip` со страницы
   [Releases](https://github.com/Samoiloff90/capacity-manager/releases).
2. Распакуйте архив двойным щелчком. Если Safari распаковал его сам, `Capacity Planner.app`
   уже лежит в «Загрузках».
3. Перенесите `Capacity Planner.app` в папку «Программы» внутри домашней папки
   (`~/Applications`); если такой папки нет, создайте её. Права администратора для этого
   не нужны. Предыдущую версию замените.
4. Запустите приложение двойным щелчком. Если macOS сообщит, что приложение не открыто:
   - нажмите «Готово», затем откройте «Системные настройки → Конфиденциальность и
     безопасность» и нажмите **«Всё равно открыть»**. Кнопка появляется после попытки
     запуска примерно на час и спрашивает пароль. На Mac с управлением ИТ её может не
     быть. «Правый клик → Открыть» на macOS 15 и новее этот запрет больше не снимает;
   - второй способ — в «Терминале»:
     `xattr -dr com.apple.quarantine "$HOME/Applications/Capacity Planner.app"`.

   Если ИТ-политика запрещает запуск, не обходите её (DEC-023). Сборка подписана ad-hoc,
   без сертификата разработчика и нотаризации (DEC-023a).

Что проверить на Mac и как сообщить результат —
[чек-лист](docs/audit/MACOS_BUILD.md#чек-лист-на-mac). В нём есть пункт о сети со скриптом
`capacity-network-watch-macos.sh` из того же релиза.

## Короткая ручная проверка

Используйте тестовые имена и отдельную пустую папку.

1. Введите **«Название команды»** и нажмите **«Выбрать папку и создать»**.
   Выберите подготовленную пустую папку. В шапке должны появиться название и путь.
2. Укажите **2026 год, 4 квартал**, нажмите **«Создать квартал»**.
   В разделе **«Календарь»** должны быть октябрь, ноябрь и декабрь; исходно — 64 рабочих дня.
3. В разделе **«Команда»** нажмите **«Добавить сотрудника»**, задайте тестовое имя,
   компетенцию и ставку **0,5**. После завершения ввода доступно **256,00 ч**.
4. В разделе **«Отсутствия»** нажмите **«Добавить отсутствие»**, выберите этого
   сотрудника и период **01.10.2026–02.10.2026**. Ожидается **248,00 ч**. Затем в календаре
   отметьте **03.10.2026** как рабочий день — получится **252,00 ч**.
5. В разделе **«Распределение»** добавьте направления «Продукт» — **20%** и
   «Встречи и прочее» — **80%**. Бюджеты должны быть **50,40 ч** и **201,60 ч**;
   предупреждение о сумме долей должно исчезнуть.
6. Нажмите **«Сохранить квартал»**, затем **«Закрыть проект»**. Через
   **«Открыть папку проекта»** выберите ту же папку. Проверьте имя сотрудника,
   ставку, отсутствие, поправку календаря, доли и итоги.
7. Через **«Изменить название команды»** задайте другое название и нажмите
   **«Сохранить название»**. После повторного открытия название должно сохраниться;
   имя самой папки не меняется.
8. Измените ставку без сохранения и нажмите **«Закрыть проект»**. В окне
   **«Несохранённые изменения»** выберите **«Вернуться»**: введённое значение
   должно остаться. **«Не сохранять»** закрывает проект с отказом от этих правок.

## Проверить задачи и дефицит

Откройте сохранённый план из примера выше: у команды **252 ч**, бюджет продукта —
**50,40 ч**, «Встречи и прочее» — **201,60 ч**.

1. Во вкладке **«Задачи»** добавьте две задачи продукта с оценками **30** и **25 ч**.
   Потребность продукта должна быть **55,00 ч**, дефицит — **4,60 ч**. Сохранение разрешено.
2. Добавьте задачу с названием и направлением, оставив оценку пустой: появится
   отметка отсутствующей оценки. Потребность станет неполной, дефицит — **не менее 4,60 ч**.
   Введите явный **0** — результат снова будет полным.
3. Перенесите задачу на 25 ч в «Встречи и прочее» через её поле направления:
   остаток продукта будет **20,40 ч**, второго направления — **176,60 ч**.
4. Нажмите удаление задачи и отмените его: строка должна сохраниться. Повторите
   удаление с подтверждением — задача исчезнет, свод пересчитается.
5. Сохраните квартал, закройте и откройте папку проекта: задачи, оценки, направления
   и результаты должны восстановиться. Для дробных оценок подходят запятая и точка.

Пустая оценка не равна нулю. При пропущенных оценках или сумме долей не 100%
остаток предварительный. Часы не переносятся между направлениями автоматически.
Общий остаток часов не подтверждает достаточность каждой отдельной компетенции.

Дополнительно создайте второй квартал или проект: его состав и календарь должны
редактироваться независимо. Для года вне встроенного календаря сначала требуется
отметить подтверждение ручной проверки; такой календарь не считается готовым
производственным календарём РФ автоматически.

## Выгрузить отчёт

Отчёт строится по **сохранённому** кварталу. Пока есть несохранённые изменения, кнопка
**«Выгрузить отчёт»** в шапке квартала неактивна, рядом подсказка **«Сохраните квартал»**.

1. Откройте сохранённый план из примера выше и нажмите **«Выгрузить отчёт»**.
2. В системном окне «Сохранить как» предложено имя «Capacity {команда} 2026 Q4.xlsx».
   Выберите папку и сохраните. Появится сообщение «Отчёт сохранён: …» с путём к файлу.
   Отмена окна ничего не записывает.
3. В файле шесть листов:
   - **Сводка** — команда, период, дата выгрузки, статус плана и причины, если он
     предварительный, календарь, рабочие дни, доступные часы, сумма долей, потребность;
   - **Люди** — со строкой «Итого»;
   - **Компетенции**;
   - **Направления** — со статусом, например «Дефицит 4,60 ч»;
   - **Задачи** — пустая оценка показана как «Не оценена»;
   - **Отсутствия**.

Цифры те же, что на экране: формулы в файле не пересчитываются. Часы округлены до 0,01,
итоги посчитаны по точным значениям. Если файл с тем же именем открыт в Excel, закройте
его и повторите выгрузку. Подробности и границы проверки —
[отчёт XLSX](docs/audit/REPORT_EXPORT.md).

## Запуск для разработки

Для разработки нужны Node.js/npm, Rust/Cargo и платформенные инструменты сборки
Tauri. Зависимости устанавливаются при подготовке среды; эта процедура может
требовать интернет. Работа готового приложения без сети проверяется отдельно.

Из корня проекта:

```powershell
npm ci
npm run tauri dev
```

`npm run dev` запускает только frontend; для работы SQLite нужен desktop-запуск Tauri.
После правки `src/export/fflate-sync-zip.ts` запускайте dev-сервер с `--force`:
кеш предварительной сборки зависимостей Vite не отслеживает этот файл.

## Сборка в GitHub Actions

Workflow [Build](.github/workflows/build.yml) запускается:
- при push кода в `main`; правки только `*.md` и `docs/` его не запускают;
- при push тега `vX.Y.Z` — тогда он ещё и публикует релиз;
- вручную: Actions → Build → Run workflow.

Секретов в нём нет. Сборки каждого push — тестовые: они лежат в Artifacts запуска
30 дней, для скачивания нужен вход. Пользователям нужны релизы.

- **macOS arm64** (`macos-26`):
  - сборка `.app` с ad-hoc подписью, проверка Info.plist, архитектуры и подписи;
  - zip через `ditto`;
  - запуск копии, распакованной из этого zip (без карантина: Gatekeeper не проверяется),
    и выход через Apple Event `quit`. Во время запуска работает скрипт
    `capacity-network-watch-macos.sh`, его отчёт о соединениях попадает в сводку запуска;
  - Vitest, TypeScript, контрольный калькулятор, rustfmt и `cargo test`.
- **Windows x64** (`windows-2025`): release EXE, portable ZIP скриптом
  `scripts/package-windows.ps1` с проверкой архива, затем Vitest, TypeScript и `cargo test`.

Сначала выполняются сборка и выгрузка артефактов, потом тесты: упавший тест не лишает
сборки, но запуск остаётся красным. Ошибки шагов публикуются аннотациями
(`scripts/ci-run.sh`) — их видно без входа в GitHub, в отличие от полных логов.

### Выпуск релиза (DEC-025)

Релиз выпускается только по команде PO.

1. Поменяйте версию: `npm version X.Y.Z --no-git-tag-version` (меняет `package.json` и
   `package-lock.json`), затем вручную в `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml`,
   затем `cargo update -p capacity-planner --offline --manifest-path src-tauri/Cargo.toml`.
   Тест `tests/app-version.test.ts` проверяет, что версии совпадают. Используйте только
   X.Y.Z: версии с суффиксом (`-rc.1`) не проверялись в сборке для Mac.
2. Напишите описание `docs/releases/vX.Y.Z.md` по образцу предыдущего.
3. Сделайте коммит и push в `main`, дождитесь зелёного Build. Если менялось только
   описание, Build на `main` не запустится, и проверкой будет запуск по тегу.
4. `git tag -a vX.Y.Z -m "Capacity Planner X.Y.Z"` и `git push origin vX.Y.Z` — только
   этот тег, не `--tags`.

Сначала `scripts/check-release.mjs` сверяет тег с версией и наличием описания. Затем
workflow собирает обе сборки заново, проверяет контрольные суммы и публикует релиз.
Описание в релизе — файл из `docs/releases` плюс таблица SHA-256. Версии 0.x и версии с
суффиксом выходят как Pre-release. Уже опубликованный релиз workflow не
перезаписывает; исправление выпускается новой версией.

Скачивание, имена файлов, контрольные суммы и описание проверяет job `release-check` при
каждой сборке, поэтому к тегу этот путь уже проверен. Если запуск по тегу всё же упал до
публикации, релиза нет, а тег остался. Исправьте причину и выпустите следующую версию
(X.Y.Z+1). Удалить тег и поставить его заново — тоже push, только по решению PO.

Иконка рисуется в `src-tauri/icons/app-icon.svg`; `app-icon-macos.svg` — тот же рисунок
по сетке иконок Apple. После правки SVG:

```powershell
npx tauri icon src-tauri/icons/app-icon.svg
npx tauri icon src-tauri/icons/app-icon-macos.svg -o <временная-папка>
```

Из временной папки скопируйте только `icon.icns` в `src-tauri/icons/`, удалите
созданные `Square*Logo.png`, `StoreLogo.png`, `android/` и `ios/`. Cargo может не
перевстроить иконку в EXE — выполните `cargo clean -p capacity-planner --release`;
Проводник Windows тоже кеширует иконки.
