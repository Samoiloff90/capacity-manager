# Квартальный планировщик — технический план

Дата: 2026-10-06. Статус: согласован PO с уточнениями DEC-042–DEC-048. Идёт этап 1 в
отдельной ветке; push и выпуск — только по команде PO.

Основа — решения DEC-029–DEC-048 (../product/QUARTER_PLANNING.md) и финальный комплект
сценариев (../product/QUARTER_PLANNING_UX.md). Меняем существующее приложение 0.3.0 по
частям, без переписывания. Local-first остаётся: без сервера, аккаунтов, облака и
обязательного интернета; модель «открыть проект → изменить квартал → сохранить» и системное
окно «Сохранить как» сохраняются. Интеграции (API Kaiten, MCP, модели) в эту версию не
входят (DEC-048).

## Что есть сейчас (0.3.0)

- Проект — папка с `capacity.sqlite`. Квартал — одна строка `quarter_plans` с полным
  снимком в JSON. Версия схемы файла 1, версия снимка 1; с 0.1.0 формат не менялся, поэтому
  проекты 0.1.0, 0.2.0 и 0.3.0 устроены одинаково.
- В снимке: календарь, сотрудники со ставками, компетенции, отсутствия, направления с
  долями, задачи с одной оценкой в часах. Пусто — «не оценена», 0 допустим, дробные часы
  хранятся точным десятичным числом.
- Расчёт — `src/domain/capacity`, запись — `src/db/project-snapshots.ts`, проверка,
  открытие и закрытие файла — Rust-модуль `project_store`. Файл другой версии отклоняется
  без изменений; 0.3.0 отвечает «Версия проекта не поддерживается».

## Модель данных: снимок версии 2

Внутренние имена остаются: `directions` — источники, `tasks` — работы (DEC-042: ради подписей
код и формат не переименовываются). Добавляются поля:

- у направления: `kind` — «Работы» или «Резерв»; `percent` может быть пустым («доля не
  задана»); `memberPercents` — свои доли сотрудников у резерва (DEC-038);
- у задачи: `mark` — кандидат («На рассмотрении»), «В плане квартала» или «Не в этом
  квартале»; `link` и `comment`. Оценка — прежнее точное число или пусто; 0 и пусто
  различаются (DEC-043).

Календарь, сотрудники, компетенции и отсутствия не меняются. Данные сессии в файл не
пишутся: незаконченный ввод, запомненный режим добавления, отмена, вставки и пропущенные
строки.

## Совместимость (DEC-044)

1. **Открытие не меняет файл.** Снимок версии 1 переводится в версию 2 в памяти:
   направление — источник «Работы» с той же долей, задача — «В плане квартала» с той же
   оценкой, ссылка и комментарий пустые. Числа остаются прежними. «Встречи» в резерв не
   превращаются.
2. **Первое сохранение старого проекта** — любая запись квартала, включая создание нового
   квартала. Сначала окно: «После обновления формата этот файл нельзя будет открыть в
   версии 0.3.0. Перед сохранением будет создана резервная копия исходного проекта». Кнопки
   «Обновить и сохранить» и «Отмена». Отмена ничего не меняет, изменения остаются
   несохранёнными.
3. **Порядок обновления** (Rust `project_store`, проект занят этим окном):
   1. повторная проверка файла;
   2. резервная копия `capacity.sqlite` в папке проекта
      (`capacity-backup-format1-ГГГГММДД-ЧЧММСС.sqlite`, без перезаписи существующих
      файлов, с записью на диск);
   3. проверка копии: побайтно совпадает с исходным файлом и открывается как проект;
   4. в одной транзакции — таблица кварталов с новым ограничением версий, перенос строк
      без изменений, версия схемы 2;
   5. проверка результата;
   6. сохранение квартала в снимке версии 2.

   После этого приложение показывает путь к копии.
4. **Сбои:**
   - копию не удалось создать или проверить — исходный файл не меняется;
   - ошибка в транзакции — откат, файл остаётся версии 1;
   - прерывание — SQLite откатывает незавершённую транзакцию при следующем открытии.
5. **Остальные кварталы** остаются в снимке версии 1, пока их не сохранят. Без явного
   действия квартал не пересчитывается (DEC-038).
6. **Восстановление.** Закрыть проект и поставить копию вместо `capacity.sqlite`. Копия —
   прежний файл без изменений: его открывает и 0.3.0, и новая версия. Порядок описан в
   README.

## Расчёт

Остаётся в `src/domain/capacity`, вне React. Ёмкость людей, календарь, ставки и отсутствия
считаются как сейчас.

- Квота источника = доступная ёмкость × доля. Резерв = сумма по людям: доступные часы ×
  своя доля сотрудника или общая. Доли считаются от всей доступной ёмкости.
- Занято = сумма полных оценок работ «В плане квартала»; работы на рассмотрении и «Не в
  этом квартале» бюджет не занимают. Работы без оценки дают «не менее» / «не более».
- Единица — человеко-часы (DEC-047). Остаток и перебор — в часах, без автоматических
  исправлений.

## Интерфейс

- Вкладки «Распределение» и «Задачи» заменяются вкладками «Источники и доли» и «План
  квартала» по финальному комплекту.
- Подписи, последствия и пояснения (i) — по DEC-042. Пояснения расширяют существующий
  модуль текстов `src/app/info-texts.ts` и подсказку `InfoHint`:
  - открываются мышью и клавиатурой;
  - помещаются в окно;
  - закрываются по Esc.
- Короткая страница «Как составить план квартала» открывается из шапки.
- «Команда», «Календарь», «Отсутствия», шапка, сохранение, Ctrl+S / ⌘S, окно
  «Несохранённые изменения», выбор и создание квартала, общий отчёт XLSX работают как
  раньше. Работающие возможности не удаляются (DEC-046).

## Отчёты, ссылки, буфер обмена

- **Отчёт заказчику:** текст в буфер обмена и XLSX одного источника через существующее
  окно «Сохранить как». Запрещённые в имени файла символы заменяются.
- **Общий отчёт:** листы «Источники» и «Работы» вместо «Направления» и «Задачи»; резерв по
  людям — в листе «Люди».
- **«Открыть в Kaiten»** (DEC-045): `tauri-plugin-opener` совместимой версии вызывается
  только из Rust-команды. Команда:
  - проверяет адрес в обработчике: только `http`/`https`, без учётных данных в адресе,
    ограниченная длина;
  - не открывает файлы и не запускает команды.

  Интерфейс прав на плагин не получает. Тест сетевых вызовов разрешает только эту
  команду.
- **«Скопировать ссылку»** остаётся. Если буфер недоступен, текст выделяется для ручного
  копирования.

## Этапы

На каждом этапе: план и «ок» PO, код, проверки, независимое ревью, небольшие коммиты.

1. **Формат и совместимость** — подробнее ниже.
2. **Расчёт:** источники, резерв по людям, признаки планирования, итоги.
3. **«Источники и доли»** и окно резерва.
4. **«План квартала»:**
   - таблица источников и рабочая область;
   - добавление, изменение, перенос и удаление работы;
   - «Отменить»;
   - незаконченный ввод;
   - подписи и пояснения (i);
   - страница «Как составить план квартала».

   После этапа — **промежуточная сборка** с основным путём (DEC-046): открыть тестовый
   проект → бюджеты источников → работа в часах → в план → остаток → сохранить → открыть
   снова.
5. **Вставка строк из таблицы.**
6. **Отчёт заказчику, ссылки Kaiten, общий отчёт.**
7. **Новый квартал** с копированием нерешённых работ.
8. **Сборка 0.4.0** (пробная, DEC-025):
   - сценарии smoke;
   - проверка сети;
   - документы;
   - выпуск по команде PO.

### Этап 1 — формат и совместимость

**Результат.**

- **Формат.** Снимок версии 2 с новыми полями и их проверкой. Перевод снимков версии 1 в
  памяти. Схема файла 2. Новые проекты создаются сразу в новом формате.
- **Первое сохранение старого проекта.**
  - Окно с предупреждением.
  - Резервная копия, проверка копии, обновление в одной транзакции, затем сохранение.
  - Сообщение с путём копии.
  - При отмене или любой ошибке исходный файл не меняется.
- **Приложение внешне как 0.3.0.** Вкладки «Распределение» и «Задачи» работают на снимке
  версии 2, все прежние возможности на месте. Новые экраны — этапы 3–4.

**Проверки.**

- **Vitest — перевод формата:**
  - перевод снимка версии 1 и проверка формата версии 2;
  - те же числа на тестовых кварталах, что считала 0.3.0: эталон записан до изменения кода;
  - контрольный пример DEC-041: квота 250 ч, другие работы в плане — 200 ч; добавили
    работу на 28 ч — занято 228 ч, осталось 22 ч; изменили её оценку на 34 ч — занято
    234 ч, осталось 16 ч;
  - 0 и пусто различаются.
- **Vitest — окно обновления:** сохранение старого проекта показывает окно; отмена ничего
  не пишет; подтверждение — копия, обновление, сохранение и путь копии; ошибка
  обновления — ничего не сохранено.
- **Rust:**
  - открытие файла версии 1 не меняет его побайтно;
  - копия совпадает с исходником и открывается;
  - ошибка копии — без изменений;
  - сбой внутри транзакции — откат;
  - прерванное обновление после повторного открытия даёт исправный файл версии 1;
  - восстановление из копии;
  - кварталы версий 1 и 2 в одном файле;
  - схема 3 отклоняется;
  - проверка версии 0.3.0 отклоняет файл схемы 2.
- **Сборка:** `npm test`, `tsc`, `npm run build`, Rust-тесты, `npm run tauri build`.
- **Сохранённый проект прежней версии:** проект с тестовыми данными, созданный сборкой
  0.3.0, открывается новой сборкой с теми же числами, сохраняется с обновлением формата и
  снова открывается. Реальные проекты PO не используются.

**Не входит:** новые экраны и расчёт резерва и признаков (этапы 2–4), проверка на Mac.

## Проверки всей версии

- **Расчёт:**
  - резерв: 80 ч × 30% + 40 ч × 40% = 40 ч (DEC-038);
  - 25% от 1 000 ч = 250 ч; после падения до 800 ч — 200 ч; при 230 ч в плане перебор
    30 ч (DEC-031);
  - контрольный пример DEC-041 полностью;
  - пустая доля и сумма долей больше 100%;
  - ёмкость 0 без деления на ноль;
  - размер «M» в часы не переводится.
- **Совместимость:** перевод снимков версии 1 без изменения чисел; обновление файла с копией
  и восстановлением; проекты прежних версий с тестовыми данными открываются, сохраняются и
  открываются снова.
- **Windows, собранный EXE:**
  - `webview-smoke`;
  - `report-export-smoke` (XLSX заказчику через «Сохранить как»);
  - `portable-reopen-smoke` (обновление формата и повторное открытие);
  - проверка сети по NETWORK_CHECK.md: приложение само ничего не отправляет; ссылку
    открывает системный браузер.
- **Mac:**
  - сборка и тесты — в GitHub Actions после разрешённого push;
  - на Mac PO — по MACOS_BUILD.md, дополненному сценариями QUARTER_PLANNING_UX.md;
  - проверка браузерного прототипа не считается проверкой на Mac.
