# Квартальный планировщик — технический план первой сборки

Дата: 2026-10-06. Статус: на согласовании PO. Код, зависимости и данные приложения не
менялись.

Основа — решения DEC-029–DEC-041 (../product/QUARTER_PLANNING.md) и финальный комплект
сценариев (../product/QUARTER_PLANNING_UX.md). Меняем существующее приложение 0.3.0 по
частям, без переписывания. Local-first остаётся: без сервера, аккаунтов, облака и
обязательного интернета; модель «открыть проект → изменить квартал → сохранить» и
системное окно «Сохранить как» сохраняются.

## Что есть сейчас

- Проект — папка с `capacity.sqlite`. Квартал — одна строка `quarter_plans` с полным
  снимком в JSON (`payload_json`). Версия схемы файла — 1, версия снимка — 1. С 0.1.0
  формат не менялся, поэтому проекты 0.1.0, 0.2.0 и 0.3.0 устроены одинаково.
- В снимке: календарь, сотрудники со ставками, компетенции, отсутствия, направления с
  долями, задачи с одной оценкой в часах. Пустая оценка — «не оценена», 0 допустим,
  дробные часы хранятся точным десятичным числом.
- Ссылок, комментариев, признаков планирования, резерва и своих долей сотрудников в
  снимке нет. Размеров работ нет ни в коде, ни в формате, поэтому миграция для них не
  нужна (DEC-041).
- Расчёт — `src/domain/capacity`, сохранение квартала — `src/db/project-snapshots.ts`
  (одна запись с проверкой ревизии), проверка, открытие и закрытие файла — Rust-модуль
  `project_store`. Миграций между версиями формата пока нет: файл другой версии
  отклоняется без изменений.

## Модель данных: снимок версии 2

- **Источники** вместо направлений: `sources[{ id, name, kind, percent, memberPercents }]`.
  - `kind` — «Работы» (`work`) или «Резерв» (`reserve`).
  - `percent` — доля; пусто — «доля не задана», это не ошибка.
  - `memberPercents` — свои доли сотрудников, только у резерва (DEC-038).
- **Работы** вместо задач: `works[{ id, name, sourceId, mark, estimateHours, link, comment }]`.
  - `mark` — «Кандидат», «В плане» или «Не в этом квартале».
  - `estimateHours` — полная оценка в часах (DEC-041), то же точное десятичное число,
    что в 0.3.0.
- Календарь, сотрудники, компетенции и отсутствия не меняются.
- В файл не пишутся данные сессии: незаконченный ввод, запомненный выбор «Кандидаты /
  В план», одна отмена последнего действия, «Отменить вставку», пропущенные строки
  вставки.

## Совместимость с проектами 0.1.0–0.3.0

1. **Чтение старого квартала.** Снимок версии 1 переводится в версию 2 в памяти:
   - направление становится источником «Работы» с той же долей;
   - задача становится работой «В плане» с той же оценкой; ссылка и комментарий пустые.

   Числа не меняются:
   - квота = прежний бюджет направления;
   - занято = прежняя потребность по задачам;
   - остаток тот же.

   Это проверяют тесты (раздел «Проверки»).
2. **«Встречи» не превращаются в резерв автоматически.** Угадывать по названию нельзя
   (Q-022). Пользователь сам выбирает вид «Резерв» у источника без работ. Числа при
   этом не меняются: без своих долей резерв = доля × доступная ёмкость. В квартале из
   прежней версии один раз показывается подсказка об этом.
3. **Квартал переписывается только при сохранении.** Пока пользователь его не
   сохранил, в файле остаётся прежний снимок. Без явного действия квартал не
   пересчитывается (DEC-038).
4. **Обновление файла проекта.** Новая схема 2 допускает в одном файле снимки обеих
   версий. Предлагаю переводить файл на схему 2 при открытии и только с согласия
   пользователя. Окно предупреждает, что прежняя версия приложения откроет только
   копию, и предлагает «Обновить и открыть» или «Отмена». Копия прежнего файла
   сохраняется рядом, в папке проекта.
5. **Порядок обновления** (по LOCAL_PROJECTS.md, Rust `project_store`):
   1. занять папку;
   2. проверить, что это наш файл версии 1;
   3. сделать копию файла с записью на диск;
   4. в одной транзакции пересоздать таблицу кварталов с новым ограничением версий,
      перенести строки без изменений и записать версию схемы 2;
   5. проверить результат.

   При ошибке транзакция откатывается, исходный файл и копия остаются. Чужие и
   повреждённые файлы не обновляются.
6. **Прежняя версия.** 0.3.0 файл схемы 2 не откроет: покажет «Версия проекта не
   поддерживается» и папку не изменит. Это поведение уже покрыто тестом.

## Расчёт

Расчёт остаётся в `src/domain/capacity`, вне React. Доступная ёмкость людей, календарь,
ставки и отсутствия считаются как сейчас.

- Квота источника = доступная ёмкость × доля.
- Резерв считается по людям: доступные часы × своя доля сотрудника или общая. Доли
  заказчиков считаются от всей доступной ёмкости.
- Занято = сумма полных оценок работ «В плане». Кандидаты и «Не в этом квартале» бюджет
  не занимают.
- Неоценённые работы дают «занято не менее», «остаток не более» и своё число.
- Остаток и перебор — в часах. Нераспределённые часы и сумма долей больше 100%
  показываются без автоматических исправлений.

## Интерфейс

- Вкладки «Распределение» и «Задачи» заменяются вкладками «Источники и доли» и «План
  квартала» по финальному комплекту.
- Без изменений остаются вкладки «Команда», «Календарь», «Отсутствия», шапка, сохранение,
  Ctrl+S / ⌘S и окно «Несохранённые изменения».
- Подтверждения — через диалоги в React, без `window.confirm`.
- Служебные панели прототипа в приложение не переносятся.

## Отчёты, ссылки, буфер обмена

- **Отчёт заказчику** по одному источнику:
  - текст копируется в буфер обмена;
  - XLSX сохраняется через существующее окно «Сохранить как» (`report_save_xlsx`);
  - имя файла по умолчанию — «источник — квартал»; символы, запрещённые в именах
    файлов, заменяются;
  - модель отчёта строится в `src/export`.
- **Общий отчёт для менеджера:**
  - листы «Источники» и «Работы» вместо листов «Направления» и «Задачи»;
  - резерв по людям — в листе «Люди»;
  - остальные листы как сейчас.
- **«Скопировать ссылку»** использует буфер обмена.
- **«Открыть в Kaiten».** Добавляется узкая Rust-команда: она открывает только
  http(s)-ссылку и только по нажатию пользователя.
  - Нужна официальная библиотека Tauri `tauri-plugin-opener`, вызываемая только из
    Rust. Интерфейс прав на неё не получает.
  - Тест сетевых вызовов расширяется: другие способы открыть ссылку остаются под
    запретом.
  - Это новая зависимость, поэтому нужно ваше решение.
- **Буфер обмена** — стандартный API браузерного движка. Если система откажет, текст
  выделяется для ручного копирования, как в прототипе.
- Вставку строк пользователь делает сам (Ctrl+V / ⌘V), поэтому чтение буфера
  приложению не нужно.

## Этапы

На каждом этапе:
- отдельный план в Plan mode и ваше «ок»;
- код и проверки;
- независимое ревью;
- небольшие коммиты от noreply-автора;
- push только по вашей команде.

1. **Формат и совместимость:**
   - снимок версии 2;
   - перевод из версии 1;
   - обновление файла до схемы 2 с копией и подтверждением;
   - тесты на чистой и заполненной тестовой БД и на проектах 0.1.0 и 0.3.0.
2. **Расчёт:** источники, резерв по людям, работы с признаками планирования, итоги;
   тесты.
3. **«Источники и доли»** и окно резерва со своими долями сотрудников.
4. **«План квартала»:**
   - таблица источников и рабочая область источника;
   - добавление, изменение, перенос и удаление работы;
   - «Отменить»;
   - незаконченный ввод.
5. **Вставка строк из таблицы.**
6. **Отчёт заказчику, ссылки Kaiten, общий отчёт.**
7. **Новый квартал** с копированием нерешённых работ.
8. **Сборка:**
   - сценарии smoke на собранном EXE;
   - проверка сети;
   - документы;
   - версия 0.4.0 как пробная (DEC-025), выпуск по вашей команде.

Есть и более короткий вариант первой сборки: этапы 1–4 и 8. В нём нет вставки, отчёта
заказчику, ссылок Kaiten и копирования работ в новый квартал. Выбор за вами.

## Проверки

- **Vitest — расчёт:**
  - резерв: 80 ч × 30% + 40 ч × 40% = 40 ч (DEC-038);
  - 25% от 1 000 ч = 250 ч; после падения до 800 ч — 200 ч; при 230 ч в плане перебор
    30 ч (DEC-031);
  - квота 250 ч, в плане 200 ч: работа на 28 ч даёт 228 ч занято и 22 ч остатка, а
    оценка 34 ч — 234 ч и 16 ч (DEC-041);
  - пустая оценка не равна 0;
  - пустая доля и сумма долей больше 100%;
  - ёмкость 0 без деления на ноль;
  - размер «M» в часы не переводится.
- **Совместимость чисел.** Для тестовых снимков версии 1 (квартал из README, приёмочный
  набор расчётов) расчёт 0.3.0 и новый расчёт после перевода дают одни и те же
  значения:
  - доступно;
  - бюджеты и квоты;
  - потребность и занято;
  - остатки;
  - число неоценённых.
- **Rust:**
  - файл версии 1 после подтверждения становится схемой 2;
  - копия побайтно совпадает с исходным файлом;
  - сбой посреди обновления откатывается, исходный файл не тронут;
  - снимки обеих версий в одном файле читаются;
  - схема 3 отклоняется;
  - файл схемы 2 отклоняется проверкой версии 0.3.0.
- **Сохранённые проекты прежних версий.**
  1. Портативные сборки 0.1.0 и 0.3.0 создают проекты с тестовыми данными по сценарию
     smoke.
  2. Новая сборка открывает их и показывает те же числа.
  3. Квартал сохраняется и открывается снова.

  Реальные проекты и выгрузки PO не используются.
- **Сборка на Windows:**
  - `npm test`, `tsc`, `npm run build`, Rust-тесты, `npm run tauri build`;
  - на собранном EXE `webview-smoke`, `report-export-smoke` (XLSX заказчику через
    «Сохранить как») и `portable-reopen-smoke` (обновление формата и повторное
    открытие);
  - проверка сети по NETWORK_CHECK.md.
- **Mac:**
  - сборка и тесты — в GitHub Actions;
  - на вашем Mac — по чек-листу MACOS_BUILD.md, дополненному сценариями из
    QUARTER_PLANNING_UX.md;
  - без запуска на Mac не заявляем, что там всё работает.

- Импорт файлов и PDF.
- Интеграция с API Kaiten.
- Исправление отображения спринтов (Q-021).
- Перевод коэффициента 70% / 60% в резерв (Q-022).
- Автосохранение.
