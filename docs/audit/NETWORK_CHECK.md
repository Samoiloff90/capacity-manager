# Проверка сети (DEC-023, этап 4)

Статус на 2026-09-26, версии 0.1.0 и 0.2.0:
- **Windows — проверено.**
  - Маркеров данных команды в трафике нет.
  - Контрольный прогон показывает, что методика находит отправленный маркер.
  - Одно соединение движка с сервером Microsoft идёт вне NetLog, его содержимое не
    проверено (ниже).
- **macOS, сервер GitHub — проверен только простой.** Запуск и выход без данных,
  соединений нет.
- **macOS, Mac пользователя — не проверено.** Нужен запуск скрипта со сценарием
  ([MACOS_BUILD.md](MACOS_BUILD.md#чек-лист-на-mac), пункт 11).

## Что проверяется

По DEC-023:
- фоновые обращения системного движка допустимы — WebView2 на Windows, WKWebView на
  macOS;
- приложение не передаёт данные команды: имена, задачи, часы;
- в приложении нет телеметрии, сетевых функций и загрузки внешних ресурсов.

Всё это подтверждается наблюдением, а не заявлением.

## Windows: ZIP релиза 0.1.0

**Условия.**
- Windows 11 Home 10.0.26200. WebView2 154.0.4258.37 — версия из адреса запроса движка.
- `Capacity-Planner-0.1.0-windows-x64-system-webview2.zip` скачан со страницы релиза,
  SHA-256 `42e09902…83757` совпал.
- EXE запускался как поставляется. Только для его процесса заданы переменные WebView2:
  - свежий профиль;
  - NetLog в режиме `Everything`: он содержит отправленные байты уже после расшифровки
    TLS;
  - порт отладки CDP для сценария;
  - `--disable-quic`. Это отклонение от поставки: содержимое QUIC в NetLog не видно.
- Командные строки движка сверены: профиль и NetLog применились, а отключение
  `msSmartScreenProtection` приходит от самого приложения.
- Сокеты всего дерева процессов приложения записывались раз в секунду.
- **Маркеры** — две уникальные строки, латиница и кириллица. Они стояли в названиях
  команды, сотрудника и задачи и попали в предлагаемое имя файла отчёта.

**Прогоны.**

| Прогон | Что делалось | Внешние запросы в NetLog | Маркеры |
| --- | --- | --- | --- |
| Контрольный | Свежий профиль, без данных. Через CDP снята CSP, маркер намеренно отправлен POST на `example.com` | `config.edge.skype.com`, `example.com` | **Найден** в отправленных байтах на 172.66.147.243:443 (`example.com`) — методика работает |
| Свежий профиль | Проект, сотрудники, квартал, задачи, сохранение, выгрузка отчёта XLSX — всё с маркерами | только `config.edge.skype.com` (GET конфигурации Edge) | не найдены |
| Повторный запуск | Тот же профиль, открытие проекта | только `config.edge.skype.com` | не найдены |

Маркеры искались во всём, что движок отправил наружу, в разных кодировках:
UTF-8, UTF-16, %-кодирование, `\u`, base64. Тела gzip, deflate и br распаковывались.

**Сокеты.**
- У самого `capacity-planner.exe` внешних соединений нет, в том числе пока было открыто
  окно «Сохранить как».
- Все внешние соединения принадлежат процессам `msedgewebview2.exe`. По реестру ARIN
  (RDAP) все их адреса зарегистрированы на Microsoft Corporation:

| Адрес | Когда | В NetLog |
| --- | --- | --- |
| 150.171.22.17:443 | каждый прогон, в первые секунды | да |
| 52.96.79.242:443, 52.96.163.34:443 | каждый прогон; в свежем и повторном — с первых 2 с до закрытия | **нет** |
| 20.190.135.47:443 | только контрольный прогон | нет |

**Ограничение: соединение вне NetLog.**
- Главный процесс WebView2 держит TLS-соединение с адресом Microsoft 52.96.x.x:443. Это
  прямой потомок приложения без `--type`.
- В свежем и повторном прогонах соединение появляется в первые 2 с, до ввода данных. Оно
  есть и в контрольном прогоне, где данных не было.
- Его открывает не сетевой сервис Chromium, поэтому в NetLog его нет и содержимое этой
  методикой не видно.
- Имя сервера без прав администратора установить не удалось: его нет в кэше DNS, нет
  обратной записи.
- Это соединение движка, DEC-023 такие допускает. **Что оно не несёт данных команды,
  эта проверка не подтверждает.**

Та же картина была на пробном прогоне этого же дня на локальной сборке.

**Повтор на ZIP релиза 0.2.0** (SHA-256 `92416f1e…fd17743`). Отличие версии — только
встроенный календарь 2027. Результат тот же:
- контрольная метка найдена;
- в прогонах со свежим профилем и повторном меток нет;
- в NetLog из внешних хостов только `config.edge.skype.com`;
- у `capacity-planner.exe` своих внешних соединений нет;
- соединение главного процесса WebView2 с 52.96.x.x:443 вне NetLog есть в каждом
  прогоне.

## macOS

**Сервер GitHub** (`macos-26`, arm64, macOS 26.6.2).
- На каждой сборке скрипт `capacity-network-watch-macos.sh` наблюдает запуск .app,
  простой и закрытие: 22 с, 16 выборок.
- Соединений нет ни у приложения, ни у его процессов WebKit: `com.apple.WebKit.Networking`
  и `com.apple.WebKit.WebContent`. Принадлежность процессов приложению подтверждена по
  открытым файлам `local.capacity-planner`.
- Проверены сборки `5ae83f7` (`main`), теги `v0.1.0` и `v0.2.0`.
- Это простой без сценария и без данных.

**Mac пользователя — не проверено.** Инструкция —
[MACOS_BUILD.md](MACOS_BUILD.md#чек-лист-на-mac), пункт 11. Скрипт видит процессы,
адреса и порты, но не содержимое. Содержимое с маркерами проверено только на Windows.
Интерфейс и код те же, а движок другой — WebKit вместо WebView2.

## Проверяется автоматически при каждом push кода

- **`tests/no-network-apis.test.ts`.** В коде интерфейса нет `fetch`, `XMLHttpRequest`,
  `WebSocket`, `EventSource`, `sendBeacon`, Web Worker, `window.open`, внешних URL и
  сетевых плагинов Tauri. Исключение — два адреса источников календаря, которые
  показываются текстом.
- **`src-tauri/tests/desktop_policy.rs`.**
  - CSP `connect-src ipc: http://ipc.localhost`, без внешних источников.
  - Нет разрешений `fs:*`, http, shell, opener.
  - Навигация за пределы приложения запрещена. Новые окна запрещает
    `project_store/commands.rs`; отдельного теста на это нет.
- **macOS, GitHub Actions** — наблюдение за сетью при запуске и выходе (выше). Отчёт — в
  сводке запуска.

## Не проверено

- Сценарий с данными на macOS.
- Содержимое соединения главного процесса WebView2 с 52.96.x.x вне NetLog.
- QUIC: в прогонах он отключён. Холодный старт без сети.
- Системные компоненты вне дерева процессов приложения: SmartScreen Windows, Edge Update,
  системный DNS.
- Синхронизация папок OneDrive и iCloud. Её выполняет система, а не приложение; в README
  есть предупреждение.
- Соединения короче секунды в выборке сокетов; NetLog такие видит.
- Windows 10 и другие версии WebView2.

## Как повторить

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\network-check-windows.ps1 -Tag v0.1.0
```

Нужны Node.js и зависимости `npm install`. Итог записывается в
`src-tauri/target/network-check-<время>/verdict.json`. NetLog и командные строки не
публикуются: в них пути пользователя. Разбор выполняет `scripts/netlog-summary.mjs`.

Предыдущая проверка 2026-09-23, до DEC-023, описана в [WINDOWS_PORTABLE.md](WINDOWS_PORTABLE.md).
