# Сборка macOS: реализация, проверка и чек-лист

Дата: 2026-09-25. Основание: DEC-023, уточнение DEC-023a (ad-hoc подпись, сборки в
GitHub Actions, иконка).
Статус: **.app для macOS arm64 собирается в GitHub Actions, запускается на Mac-раннере и
завершается через хук выхода; все тесты на macOS проходят. На Mac PO приложение ещё не
запускалось.** Результаты запусков — ниже.

## Что сделано

- **Сборка в GitHub Actions.** Workflow [Build](../../.github/workflows/build.yml):
  - запускается при push кода в `main` и вручную;
  - job `macos` на `macos-26` (arm64, та же основная версия macOS 26, что у PO; на
    раннере 26.6.x): `.app`, zip через `ditto`;
  - job `windows` на `windows-2025`: portable ZIP текущими скриптами;
  - артефакты хранятся 30 дней, zip выгружается без второго слоя архивации;
  - секретов нет, actions закреплены по SHA коммита.
- **Подпись ad-hoc** (`bundle.macOS.signingIdentity: "-"`): без сертификата, Developer ID и
  нотаризации. По документации Tauri и отчётам пользователей, без неё macOS называет
  скачанное приложение повреждённым и не предлагает «Всё равно открыть». На Mac это не
  проверялось.
- **Иконка** — сдержанный кабанчик (выбор PO). Исходники `src-tauri/icons/app-icon.svg` и
  `app-icon-macos.svg` (сетка Apple для `icon.icns`). Тест `desktop_policy.rs` проверяет,
  что PNG из `bundle.icon` — 8-bit RGBA: иначе macOS-сборка не компилируется.
- **Меню по-русски** (`src-tauri/src/macos_app.rs`). Стандартное меню Tauri было
  английским. Меню «Правка» с системными пунктами нужно, чтобы в полях работали
  Cmd+C/V/X/A.
- **Защита выхода.** Раньше Cmd+Q, «Завершить» в меню, Dock → «Завершить» и выход из
  системы вызывали `NSApp terminate:`. В tao это сразу `RunEvent::Exit`: диалог
  «Несохранённые изменения» пропускался, черновик терялся молча. Теперь:

  | Способ | Путь |
  | --- | --- |
  | Красная кнопка, Cmd+W, «Окно → Закрыть окно» | Как и раньше: `CloseRequested` → диалог |
  | Cmd+Q, «Завершить Capacity Planner» | Свой пункт меню → закрытие главного окна → диалог |
  | Dock → «Завершить», выход из системы, AppleScript `quit` | Хук `applicationShouldTerminate:` отвечает «отмена», показывает окно и закрывает его → диалог |

  Если правок нет, окно закрывается сразу, и приложение завершается. При выходе из
  системы с открытым приложением ожидается, что macOS сообщит о прерванном выходе, а
  приложение закроется обычным путём; выход нужно повторить. Это пункт 11 чек-листа.
- **Системные окна на русском.** `src-tauri/Info.plist` объявляет локализацию `ru`.
- **Выбор папки — операция контроллера.** Если выйти из приложения, пока открыто окно
  выбора папки, закрытие дождётся окончания выбора и не уничтожит окно под открытым
  листом. Выбранная в этот момент папка не открывается.

## Что проверяет каждый запуск CI

macOS:
1. Сборка `.app` (`npm run tauri build -- --bundles app`).
2. Info.plist:
   - `CFBundleIdentifier` = `local.capacity-planner`, версия из `tauri.conf.json`;
   - `CFBundleDevelopmentRegion` и `CFBundleLocalizations` = `ru`;
   - есть `.icns`, архитектура `arm64`;
   - `codesign --verify --deep --strict`, `Signature=adhoc`.
3. Zip через `ditto`, контрольная распаковка, повторная проверка подписи, SHA-256.
4. **Запуск на раннере** копии, распакованной из того же zip, что скачивает PO:
   - приложение живо через 15 с, хук выхода установлен;
   - Apple Event `quit` → хук → закрытие окна → код выхода 0.

   Не покрыто: у этой копии нет карантина, поэтому Gatekeeper, «Всё равно открыть» и
   `xattr` не проверяются. Проверяется только выход через Apple Event без открытого
   проекта; пункт меню Cmd+Q и диалог о несохранённых правках — только на Mac.
5. Vitest, TypeScript, контрольный калькулятор, rustfmt, `cargo test`. Здесь впервые на
   APFS проверяются hard link при создании проекта, блокировка `flock` и пути
   `/private/var`. На macOS ожидается 41 Rust-тест и 1 пропущенный: тест блокировки
   файла отчёта есть только на Windows.

Windows: release EXE, ZIP с проверкой архива, Vitest, TypeScript, `cargo test`.

## Результаты

Локально, Windows 11:
- Vitest 344/344, TypeScript, 42 Rust-теста (1 ignored), `cargo fmt --check`;
- release EXE с новой иконкой (иконка извлечена из EXE и сверена), portable ZIP и его
  проверка. Сборка шла в отдельный каталог `src-tauri/target/stage3-check`: EXE этапа 2
  в `target/release` был запущен и не пересобирался.

На Windows не компилируются модуль `platform` в `macos_app.rs`, ветки
`cfg(target_os = "macos")` в `main.rs` и objc2. Тексты меню и решение о выходе
тестируются и на Windows. Независимый review дополнительно проверил компиляцию по частям:
- objc2-часть хука скомпилирована отдельно для `aarch64-apple-darwin` с objc2 0.6.4 —
  0 ошибок и 0 предупреждений;
- код, использующий API Tauri (меню, обработчики, `main.rs`), скомпилирован на Windows с
  tauri 2.11.5.

Полная сборка для macOS — только в job `macos`.

## Не проверено

- Всё, что требует живого Mac PO: пункты чек-листа ниже.
- Диалог о несохранённых правках при Cmd+Q и Dock → «Завершить». На раннере проверяется
  только выход без открытого проекта.
- Русские системные окна: `CFBundleLocalizations` проверяется в Info.plist, но не на
  экране.
- Gatekeeper под MDM. По словам PO, Gatekeeper на его Mac сейчас отключён, поэтому путь
  «Всё равно открыть» из README там не проверится. При включённом Gatekeeper возможен
  запрет ИТ.
- Excel for Mac.
- Защита выхода на Windows при завершении сеанса.

## Чек-лист на Mac

Используйте тестовые данные и отдельную пустую папку, например
`~/Documents/Capacity тест/Команда А`. Отметьте результат каждого пункта. Если что-то не
так, сообщите номер пункта и что произошло, без рабочих данных.

1. **Запуск.** Скачать и запустить по [README](../../README.md#запустить-на-mac).
   Ожидается: окно открылось; в Dock и Finder — иконка с кабанчиком.
2. **Меню.** Строка меню по-русски: «Capacity Planner», «Правка», «Окно».
   «О программе Capacity Planner» показывает версию.
3. **Правка.** В поле «Название команды» ввести текст, Cmd+A, Cmd+C, стереть, Cmd+V.
   Ожидается: текст вернулся.
4. **Проект.** Создать проект в папке с кириллицей и пробелами, пройти «Короткую ручную
   проверку» из README. Закрыть проект, открыть снова: данные на месте.
5. **Системные окна.** Окна выбора папки и «Сохранить как» — на русском.
6. **Закрытие с несохранёнными правками.** Изменить ставку, не сохраняя. Затем по очереди:
   красная кнопка, Cmd+W, Cmd+Q, Dock → «Завершить».
   - Каждый раз появляется «Несохранённые изменения».
   - «Вернуться» оставляет окно и правку.
   - В последний раз — «Не сохранять»: приложение закрылось. После повторного
     открытия правки нет.
7. **Выход, когда окно не видно.** С несохранённой правкой:
   - Cmd+H, затем Dock → «Завершить»;
   - свернуть окно, затем Dock → «Завершить»;
   - переключиться в другое приложение, затем Dock → «Завершить».

   Ожидается: окно появляется с диалогом.
8. **Выход без правок.** Cmd+Q без несохранённых правок. Ожидается: приложение закрылось
   без вопросов.
9. **Выход во время выбора папки.** Нажать «Открыть папку проекта», при открытом окне
   выбора нажать Cmd+Q. Ожидается: приложение не падает. После выбора папки или отмены
   проект не открывается, приложение закрывается.
10. **Отчёт.** Сохранить квартал, «Выгрузить отчёт»:
    - имя по умолчанию «Capacity {команда} {год} Q{квартал}.xlsx»;
    - в «Документы» и в «Загрузки». Если macOS спросит доступ к папке, ответ и текст
      запроса — в отчёт о проверке;
    - повторная выгрузка поверх — подтверждение замены;
    - отмена — файла нет;
    - открыть файл в Excel for Mac: шесть листов, цифры как на экране.
11. **Выход из системы.** Не обязательно. С открытым приложением выйти из системы.
    Ожидается: macOS сообщает, что Capacity Planner прервал выход; приложение закрылось
    или показало диалог. Запишите точный текст сообщения macOS.

Если окно перестало отвечать, выйти не получится ни через Cmd+Q, ни через Dock: выход
всегда идёт через закрытие окна. Тогда используйте «Завершить принудительно»
(Cmd+Option+Esc) и сообщите, что происходило перед этим.
