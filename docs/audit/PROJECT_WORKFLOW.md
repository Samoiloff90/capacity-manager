# Проекты, кварталы и новый расчёт

Дата: 2026-09-23. Основание: прямое разрешение PO, DEC-019.

## Результат

Новый основной сценарий: создать/открыть папку команды → выбрать год/квартал →
внести людей, ставки, отсутствия и рабочие дни → получить и сохранить расчёт.
Название команды хранится в `project_meta`; его изменение не перемещает папку.
Каждая команда имеет свою `capacity.sqlite`, каждый квартал — независимый снимок.
Выбранный квартал запоминается локально в настройках интерфейса по ID проекта.
Он не становится частью файла, передаваемого другому человеку.

Работают таблицы компетенций и участников, календарь, целодневные отсутствия,
распределение по направлениям и свод часов. Фиксированный Q2 и коэффициент 0,7
исключены из нового пользовательского потока. Направления со суммой не 100%
сохраняются как предварительное распределение с явным предупреждением.
Пустые имена, некорректные даты и числа блокируют сохранение до исправления.
Удаление человека требует подтверждения и удаляет связанные отсутствия только
в текущем квартале. Ввод задач через интерфейс — следующая задача; их расчётное
ядро и сохранение снимка уже существуют.

## Сохранность и границы компонентов

- Формулы и точные десятичные вычисления остаются в `src/domain/capacity/`.
- Прикладные SQL-запросы выполняет `src/db/project-snapshots.ts`; React SQL не содержит.
- Контроллер хранит исходную ревизию и отдельный редактируемый снимок. Поздние
  правки не теряются после завершения более раннего сохранения. Ошибка записи
  оставляет данные в форме и признак несохранённых изменений.
- Смена квартала, проекта и закрытие проверяют несохранённые поля, включая
  незаконченное переименование. Отмена сохраняет текущую форму. Неудачное
  открытие другого проекта не сбрасывает старый проект.
- Native-запуск не загружает старую `capacity.db`, не мигрирует её и не удаляет.
  Производственные команды общие с IPC-тестом; создаётся только защищённое главное окно.
- SQL capabilities допускают select/execute; прямые plugin load/close запрещены.
  FS plugin не регистрируется. Диалог допускает только выбор папки.
- CSP ограничивает сетевые ресурсы локальными assets/IPC; native callbacks
  запрещают внешнюю навигацию и новые окна. В production нет dev-server origin.

## Календарь

Встроен календарь РФ 2026, пятидневная неделя: 55/62/66/64 рабочих дня по кварталам.
Основания: [статья 112 ТК РФ, Минтруд](https://mintrud.gov.ru/labour/relationship/351)
и [постановление № 1466 от 24.09.2025](https://government.ru/docs/all/161028/).
Это атрибуция данных: приложение не загружает страницы и не обращается к ним.
Сокращённые предпраздничные часы не учитываются согласно принятой норме MVP.

С 2026-09-26 встроен и календарь РФ 2027 (DEC-026): 56/62/66/63 рабочих дня по кварталам,
рабочая суббота 20 февраля. Основания — статья 112 ТК РФ и
[постановление № 1187 от 17.09.2026](http://government.ru/dep_news/59913/). Проверка —
`tests/project-calendar.test.ts`.

В снимке сохраняются итоговые даты, источник, версия и исходные рабочие даты.
Ручные поправки сравниваются с сохранённой основой и не исчезают при открытии
или обновлении приложения. Для остальных лет пользователь явно подтверждает
ручную настройку пятидневки без праздников и переносов. Существующие снимки без
метаданных источника читаются; интерфейс предлагает проверить календарь.
Схема SQLite и версия payload не менялись: метаданные календаря необязательны.

### Настоящий WebView2

`scripts/webview-smoke.mjs` проверяет собранное окно с production assets через
локальный CDP. Отладочный порт включается переменной окружения только у тестового
процесса; в приложении нет постоянного порта или тестового API. Все проекты
создаются под игнорируемым `src-tauri/target/`, используются вымышленные данные.
Только системный диалог выбора папки подменяется тестовым ответом; все команды
проектов, SQL-запросы, SQLite, React и обработка закрытия окна настоящие.

Проверено:

1. Создание проекта в папке с кириллицей; отмена выбора папки без изменений.
2. IV квартал 2026: 64 рабочих дня, ставка 0,5 → 256 ч; два дня отсутствия →
   248 ч; добавленный вручную рабочий день 3 октября → 252 ч.
3. Направление 20% получает **50,40 ч**, второе 80% — 201,60 ч.
4. Сохранение, переименование, закрытие/открытие восстанавливают снимок,
   исходный календарь, поправку, отсутствие, ставку и выбранный квартал.
5. I квартал и ручной план 2027 независимы; неподдерживаемый год требует явного выбора.
   С 2026-09-26 (DEC-026) 2027 встроен, и `webview-smoke` проверяет ручной режим на 2028.
6. Вторая папка команды имеет собственный пустой состав; первая сохраняет 252 ч.
7. Отмена смены квартала сохраняет правки; подтверждённый отказ восстанавливает
   сохранённый снимок. Настоящая native-команда закрытия окна вызывает предупреждение;
   отмена сохраняет окно и изменённую ставку.
8. Внешний fetch вызывает событие нарушения `connect-src` — это не просто ошибка DNS.
   Прямой SQL load отклоняется. Внешняя навигация и новое окно не открываются.
9. Снимок экрана проверен визуально: таблица и сводка помещаются, суммы читаемы.

## Что ещё не доказано

Автоматический WebView smoke не проверяет взаимодействие с системным выбором
папки мышью. Первый запуск распакованного выпуска без администратора на чистой
корпоративной Windows, наличие WebView2, процессные исходящие соединения и macOS
не проверены. Запрет fetch из WebView не заменяет наблюдение всего дерева процессов.
Используется debug EXE; старый release EXE оставлен без замены, поскольку он открыт
у пользователя. Не отключались системные защиты или проверки подписи.

Не включены в этот шаг: UI задач, импорт Excel/JSON, отчёты, копирование состава
из предыдущего квартала, обновления формата и синхронизация.
