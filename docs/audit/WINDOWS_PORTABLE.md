# Проверка расчётов и пробный ZIP Windows

Дата: 2026-09-23. Основание: DEC-021. Цель PO — Windows 10 и 11;
наличие WebView2 на целевых компьютерах неизвестно.

**Статус: расчётная приёмка пройдена; пробный ZIP подготовлен. Выпуск для рабочих
данных с требованием полного отсутствия сети заблокирован:** в отдельном тестовом
профиле WebView2 зафиксированы фоновые внешние подключения. Это проверка прототипа
доставки, а не подтверждение выполнения всех требований REQ-002/005/006.

## Что изменено

- Расчётные формулы не менялись. Добавлен независимый Python-эталон на
  `datetime`/`Fraction`: 12 ручных сценариев и 24 воспроизводимых комбинации.
  Vitest сравнивает полный результат производственного ядра с эталоном.
  Метод, примеры и границы — в [CALCULATION_ACCEPTANCE.md](CALCULATION_ACCEPTANCE.md).
- Release EXE использует Windows GUI subsystem: дополнительное консольное окно
  не создаётся. Debug-режим сохранён.
- `scripts/package-windows.ps1` упаковывает уже собранный EXE в новый каталог
  `src-tauri/target/portable/`. В архиве ровно три файла: `capacity-planner.exe`,
  `README-PORTABLE.txt`, `manifest.json`. Базы, профили, логи, исходный Excel и
  исходники в архив не входят. Установщика и автоматического скачивания нет.
- `scripts/check-windows-package.ps1` проверяет состав ZIP, SHA-256, PE x64,
  GUI subsystem и встроенный манифест `asInvoker`, `uiAccess=false`.
  SHA-256 не заменяет цифровую подпись. Git commit/dirty в манифесте описывает
  исходники при упаковке, не удостоверяет происхождение произвольного EXE.

## Сеть: обнаруженное ограничение

Отдельный новый профиль WebView2 запускался с test-only аргументами
`--remote-debugging-port=19324 --log-net-log=<local path> --net-log-capture-mode=Default`.
Профиль задавался переменной окружения только дочернего тестового процесса.
После обычного workflow и CDP-offline workflow приложение закрыто штатно.
NetLog содержит запросы к `config.edge.skype.com`, `edge.microsoft.com` и
завершённые внешние TCP/SSL-соединения без `net_error`.

Это фоновые обращения runtime: отсутствие сети **не подтверждено и фактически
нарушено в проверенной среде**. Доказательств передачи содержимого проектов нет;
в проверке использованы исключительно искусственные данные. Исходный NetLog
не публикуется: он может содержать сведения о системе и профиле.

CDP offline включался после загрузки интерфейса. Его PASS подтверждает возможность
рассчитывать и сохранять без сети renderer, но не холодный первый запуск без сети,
не блокировку всего дерева процессов и не отсутствие диагностики Windows.
CSP ограничивает страницу, а не весь системный WebView2. Microsoft отдельно
описывает [диагностику WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/data-privacy)
и предназначение [browser flags для разработки](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/webview-features-flags).
В production не добавлялись экспериментальные флаги и не менялись системные политики.

До использования с рабочими данными нужен отдельный согласованный способ обеспечить
нулевые исходящие подключения на целевых ПК и проверить его. Возможности корпоративной
изоляции или изменение подхода к desktop runtime требуют решения PO/ИТ;
данный этап не подменяет исходное требование более слабым «нет собственного сервера».

## Зависимости и границы переносимости

В проверенной среде установлен WebView2 Evergreen 153.0.4234.48. Приложение
Tauri 2.11.5 / Wry 0.55.1 использует системный runtime. Таблица зависимостей EXE
содержит Windows/UCRT DLL; отдельные WebView2Loader, SQLite, VCRUNTIME/MSVCP DLL
не импортируются. Это не заменяет проверку чистой Windows 10.

Системный WebView2 **не включён** в ZIP. Fixed Version ≥120 для unpackaged Win32
на Windows 10 требует дополнительных ACL папки runtime; Microsoft также указывает
значительный размер и ответственность приложения за его обновление.
Поэтому эта поставка не объявлена универсальным самодостаточным архивом.
Источник: [Microsoft WebView2 distribution](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).

Профиль/кеш WebView2 по умолчанию размещается в пользовательском AppData.
Папка проекта выбирается отдельно. Под «переносимостью» этого пробного ZIP
понимается отсутствие установщика самого приложения, а не отсутствие внешних
компонентов или следов вне папки EXE. Подпись, корпоративный допуск, Windows 10,
холодный offline-запуск и macOS остаются открытыми проверками.

## Воспроизведение

Сначала выполните проверки и release-сборку из README. Затем в разрешённой среде PowerShell:

```powershell
.\scripts\package-windows.ps1 -ExePath .\src-tauri\target\release\capacity-planner.exe
.\scripts\check-windows-package.ps1 -ArchivePath <полный-путь-к-zip>
```

В этой среде все ExecutionPolicy scopes были `Undefined`, эффективное значение —
стандартное `Restricted`. Для локального скрипта разработчика использован отдельный
процесс `powershell -NoProfile -ExecutionPolicy RemoteSigned -File ...` с разрешением;
постоянные параметры ОС не менялись. Для запуска самого EXE PowerShell не нужен.
Корпоративные запреты исполнения этим способом не обходятся.

Dev smoke запускается только против отдельного тестового экземпляра с новым профилем:

```powershell
node --experimental-websocket scripts/webview-smoke.mjs 19324
$env:CAPACITY_SMOKE_OFFLINE='1'
node --experimental-websocket scripts/webview-smoke.mjs 19324
```

После закрытия тестового процесса и нового запуска EXE с отдельным чистым профилем:

```powershell
node --experimental-websocket scripts/portable-reopen-smoke.mjs 19324 <путь-к-workflow-smoke-result.json>
```

Артефакты проверки находятся только в игнорируемом `src-tauri/target/`.
Порт отладки и NetLog не включены в поставляемое приложение по умолчанию.

SHA-256 проверенного release EXE:
`5d23052d4b6bda19856598801a8253c99c20859b8430e26ad783e47d435c3d4d`.
В обеих извлечённых папках байты EXE совпали с release-файлом.
