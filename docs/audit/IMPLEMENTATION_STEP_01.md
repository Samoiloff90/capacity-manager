Дата: 2026-09-23. Основание: DEC-016; PO согласовал архитектуру и самостоятельное review.
Статус: первые две задачи завершены — расчётное ядро и изолированная проверка
хранилища реализованы, прошли review и проверки. Windows release-сборка успешна.

## Объём

- Новое чистое квартальное ядро в `src/domain/capacity/quarter-*`, с отдельными
  модулями дат и точных десятичных чисел; прежний калькулятор и тесты сохранены.
- Адаптер снимков в `src/db/project-snapshots.ts`: проверка чтения/записи,
  один SQL-запрос на сохранение квартала, проверка ревизии, очередь операций
  и закрытие конкретной сессии после завершения записей.
- Изолированный native-модуль `src-tauri/src/project_store/`: временные проекты
  SQLite, проверка формата, сессии, блокировка и повторное открытие.
- Исполняемые проверки связки Tauri IPC / SQL-плагин / SQLite в отдельном тестовом
  контексте без старого preload. Основной `main.rs`, capabilities и пользовательский
  путь открытия БД ещё используют прежний прототип; новый код к экранам не подключён.

## Независимое review

- Расчётное ядро: существенных ошибок формул, объединения отсутствий, точности
  процентов, дат, полноты результата и неизменяемости входа не найдено.
- Адаптер: native IPC-тест уточнён до точного UPDATE с проверками периода и версии.
  Будущий UI обязан отдельно защищать все последние несохранённые правки формы,
  включая не прошедшие валидацию; очередь репозитория не заменяет этот контроль.
- Хранилище: исправлены преждевременное освобождение блокировки при уничтожении
  владельца сессии и отмене операций, несогласованное ограничение размера при
  записи/чтении и невозможность повторного создания после ошибки. Независимый
  reviewer повторно проверил исправления; соответствующие regression-тесты прошли.
- Windows build manifest: отдельный reviewer подтвердил целевую проверку Windows/MSVC,
  сохранение Common Controls 6 и отсутствие запроса повышения прав.

## Найденная особенность Windows-тестов

Тестовый EXE сначала завершался до выполнения тестов с `STATUS_ENTRYPOINT_NOT_FOUND`.
В импортах найден `TaskDialogIndirect`; tauri-build добавлял ресурс с Common Controls 6
только bin-целям, тестовый EXE его не получал. В `build.rs` добавлено встраивание
manifest для исполняемых MSVC-целей по [официальному примеру Tauri](https://github.com/tauri-apps/tauri/blob/dev/examples/api/src-tauri/build.rs).
Manifest содержит Common Controls 6 и `asInvoker`, без повышения прав.
После изменения тот же IPC-тест запустился и прошёл.

## Что подтверждено для SQLite

На временных проектах Windows проверены пути с кириллицей, пробелами и спецсимволами;
изолированное закрытие одного из двух проектов; исключительное владение между
процессами и его освобождение после завершения процесса; восстановление последней
подтверждённой записи после реального аварийного завершения с rollback journal;
неизменность чужих, повреждённых и неподдерживаемых файлов при отказе открытия;
перенос закрытой копии; атомарность сохранения и отказ при устаревшей ревизии.

Закрытие и изменяющая стадия открытия завершаются независимо от отмены запроса.
Блокировка удерживается до закрытия физического соединения; если закрытие
невозможно подтвердить, она сохраняется до выхода процесса, без сообщения об успехе.

Технические ограничения пробной реализации:

- Поддерживается только схема v1. Тест ошибки миграции проверяет откат DDL/версии
  в транзакции на тестовой БД; рабочей цепочки обновлений и резервных копий ещё нет.
- Размер БД ограничен 128 MiB при записи и открытии. Превышение при сохранении
  возвращает ошибку с откатом записи, а не создаёт успешно сохранённый нечитаемый файл.
- Создание публикует готовую закрытую БД через hard link без перезаписи назначения.
  Нужна поддержка hard links файловой системой; работа на macOS ещё не подтверждена.
- Обычная ошибка создания очищает временную подпапку и допускает повтор в той же
  папке. Аварийное завершение процесса во время создания может оставить временную
  подпапку с UUID; автоматическая очистка таких остатков ещё не реализована.

## Границы результата и следующие проверки

Это две ограниченные инженерные задачи, не готовый пользовательский выпуск.
Учебные календари в тестах не являются нормативным календарём РФ.
Ядро принимает окончательные рабочие/нерабочие даты. Сохранение источника/версии
календаря и ручных поправок ещё требуется при интеграции нормативного календаря;
экспериментальный payload v1 пока не объявляется стабильным форматом обмена.
Отображение округлённых часов, включая очень малый дефицит, относится к UI-интеграции.

Пока не подтверждены: запуск release из ZIP на чистой Windows без администратора,
работа на macOS, отсутствие исходящих соединений собранного приложения,
восстановление пользовательского UI с несохранёнными изменениями и готовность
экранов нового процесса. Наличие установленного WebView2 на машине разработки
не доказывает portable-доставку.

Перед подключением экранов: зафиксировать формат calendar provenance, подключить
native-команды с узкими capabilities и без legacy preload, проверить оконечный
путь WebView → JS-адаптер → SQLite на временных проектах и проверить доставку.
Старую общую БД не удалять и автоматически не мигрировать.
