# Подготовка публикации и исправления первого отзыва

Дата: 2026-09-23. Основание: DEC-017–018.
Статус: изменения проверены и сохранены в очищенной локальной истории `main`;
push ожидает точного адреса репозитория.

## Изменения интерфейса

- Шапки читают сохранённое название команды из общего состояния, без имени руководителя.
- В разделе «Команда» название можно изменить, сохранить или отменить правку.
  Ошибка сохранения видна; черновик имени сохраняется при переключении разделов.
- Переименование сохраняет ID команды, состав и остальные данные. В старом
  однокомандном интерфейсе команда выбирается по минимальному ID, чтобы изменение
  имени не меняло выбор после перезапуска. В многокомандной legacy-БД это может
  отличаться от прежнего выбора первой строки по алфавиту; новый выбор проекта
  остаётся отдельной задачей.
- Новые начальные данные используют нейтральное имя команды и пустое имя руководителя.
  Существующие пользовательские названия и записи автоматически не анонимизируются.
- Исправлен выявленный при review старый дефект чистого запуска: INSERT компетенции
  теперь заполняет обязательный `code`; переименование его сохраняет. Инициализация
  справочника, квартала и месяцев последовательная, повторная попытка после ошибки разрешена.

Фиксированный Q2 2026 и коэффициент производственной загрузки в прежнем интерфейсе
остаются до подключения нового процесса. Его порядок описан в
[следующей итерации](../system/NEXT_ITERATION.md).

## Границы публикации

Исходный локальный коммит содержит рабочий Excel и персональные значения в примерах,
а также личную идентичность Git. Обычный push его потомков публикует эти объекты,
даже если позже удалить файлы. Поэтому публикуется отдельный начальный коммит
без этого родителя; исходная история и локальные материалы сохраняются на компьютере.

Из публикуемого дерева исключены исходный Excel, архивные материалы discovery,
локальные SQLite-файлы и журналы, зависимости, сборки, логи, credentials и .env.
Примеры в коде обезличены. Используется нейтральная идентичность коммита с доменом
`.invalid`, без частного адреса почты. Отправляется только явно выбранная ветка;
архивные ветки и служебные refs не отправляются.
Эта идентичность задана только для данного Git-репозитория; глобальные настройки
не изменяются. Прежняя история хранится в `local/prototype-history`. В `main`
проверен начальный коммит без родителя; исходный baseline из него недостижим.

Независимая ограниченная проверка исходников и baseline не обнаружила признаков
токенов, приватных ключей и credential-URL в просмотренных текстах. Это проверка
состава публикации, не полный аудит безопасности приложения и не гарантия
отсутствия любых секретов.

## Совместимость старого прототипа

Простая анонимизация SQL-файла меняет checksum и мешает SQLx открыть ранее созданную
БД. `project_store/legacy_compat` выполняется перед SQL preload: заранее проверяет
точную историю/схему, повторяет проверку под `BEGIN IMMEDIATE` и запускает стандартный
SQLx Migrator. Только для точных известных старых checksum разрешён alias в памяти;
исходники закреплены SHA-384, переносы строк SQL — LF через `.gitattributes`.
История миграций и персональные записи существующей v2 не переписываются.

На временных БД проверены чистое создание, заполненная v1, старые LF/CRLF checksum,
сохранение всех строк и migration metadata, отказы для неизвестных/повреждённых
состояний, rollback и конкурентный запуск. Отдельный тест выполняет фактический SQL
репозиториев компетенций и сотрудников на чистой SQLite-схеме. MockRuntime проверяет
закрытие соединения и остановку следующего plugin setup при ошибке; он не заменяет
ручной запуск настоящего WebView. Независимый reviewer принял совместимость и UI;
найденный дефект `competencies.code` исправлен до итоговых проверок.

Текущий адрес удалённого репозитория не задан. Перед push нужны проверенный
адрес получателя, проверка итогового дерева и достижимой истории коммита.
