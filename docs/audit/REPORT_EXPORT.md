# Отчёт XLSX: реализация и проверка

Дата: 2026-09-25. Основание: DEC-024 и его уточнение о формате долей и ставки.
Статус: **выгрузка реализована и проверена на Windows 11 x64**. На macOS не собиралась
и не запускалась; открытие файла в Excel здесь не проверялось.

## Что сделано

- Кнопка «Выгрузить отчёт» в шапке квартала выгружает **сохранённый** квартал.
  При несохранённых изменениях кнопка неактивна, рядом подсказка «Сохраните квартал».
  При незавершённом переименовании команды: «Сохраните или отмените новое название
  команды». Если сохранённый план не считается (неполный календарь): «Отчёт появится
  после заполнения данных».
- Модель отчёта `src/export/quarter-report.ts` ничего не пересчитывает:
  - итоги берутся из `calculateQuarterCapacity`;
  - статусы направлений — из `describeDirectionBalance`, как на экране;
  - статус плана «Готовый» или «Предварительный» и причины — из доменного правила
    `describeQuarterPlanStatus`;
  - строки идут в порядке снимка. Таблица «Часы по компетенциям» на экране переведена
    на тот же порядок: раньше её строки шли в порядке случайных id.
- Шесть листов: Сводка, Люди, Компетенции, Направления, Задачи, Отсутствия.
  - Часы — числа с форматом `#,##0.00`, округлённые так же, как на экране.
  - Доли и ставка — числа в формате «Общий», как на экране (решение PO).
  - Даты — `дд.мм.гггг`. Пустая оценка — текст «Не оценена».
  - Число с более чем 15 значащими цифрами (предел точности Excel) записывается тем же
    текстом, что на экране. Дата раньше 01.03.1900 тоже записывается текстом: Excel
    считает несуществующее 29.02.1900.
  - Шапка закреплена. Дефицит и предварительные строки выделены цветом.
- Имя файла по умолчанию: «Capacity {команда} {год} Q{квартал}». Символы, запрещённые
  в Windows и macOS, и управляющие символы удаляются, длина ограничена.
- Файл сохраняет узкая Rust-команда `report_save_xlsx`:
  - сама показывает системное окно «Сохранить как»;
  - принимает только готовые байты (не больше 2 МиБ, сигнатура ZIP);
  - пишет через временный файл и замену;
  - если целевой файл занят другой программой, показывает понятную ошибку, старый файл
    не трогает.

  Фронтенд не получает ни `fs:*`, ни `dialog:allow-save`.
- В `build.rs` объявлен app manifest, поэтому **все** команды приложения требуют явного
  разрешения. В `capabilities/default.json` разрешены только:
  - `allow-project-create`, `allow-project-open`, `allow-project-close`;
  - `allow-report-save-xlsx`.

## Найденные и обойдённые особенности библиотек

- **fflate и CSP.** `write-excel-file` 4.1.1 сжимает книгу асинхронным `zip()` из fflate.
  Любой внутренний файл от 160 000 байт тот сжимает в Web Worker из `blob:`, а CSP
  приложения такой Worker запрещает: большой отчёт завис бы. Решение: Vite/Vitest alias
  заменяет голый импорт `fflate` на `src/export/fflate-sync-zip.ts`, где `zip` построен
  на `zipSync`. CSP не менялась. В собранном бандле `new Worker` не встречается.
- **Служебные имена.** `write-excel-file` 4.1.1 индексирует общие строки обычным объектом
  JavaScript. Текст, совпадающий с именем служебного свойства объекта (`constructor`,
  `__proto__`, `toString`…), испортил бы файл. К такому тексту добавляется невидимый
  символ U+200B.

**Проверка в release-EXE** (продакшн-CSP, настоящее окно Windows 11 «Сохранить как»,
скрипт `scripts/report-export-smoke.mjs`, искусственные данные, папка вне репозитория
с кириллицей и пробелами):
- кнопка активна после сохранения; после правки неактивна с подсказкой «Сохраните квартал»;
- имя по умолчанию «Capacity Тестовая команда отчёт Q4 2026 Q4.xlsx» для команды
  «Тестовая команда: отчёт/Q4»;
- отмена — нет файла и сообщений;
- сохранение — сообщение с полным путём, файл 8,7 КБ;
- перезапись после подтверждения ОС — файл заменён;
- файл держит другая программа — ошибка «файл открыт в другой программе…», файл не
  изменён, временных файлов нет;
- 3000 задач — файл 58 КБ, около 1,4 с вместе с окном сохранения.

Окном сохранения скрипт управляет через Win32-сообщения. Содержимое сохранённых файлов
он не читает (правило CLAUDE.md): только наличие, размер и время изменения. Содержимое
книги проверяется тестами в памяти.

## Независимый review

Ещё до кода план проверили три независимых критика: Rust и ACL, TS и XLSX, соответствие
описанию PO. Их находки учтены до реализации, среди них:
- типы `fflate/browser` при `moduleResolution: Node`;
- `server.deps.inline` в Vitest;
- ошибка библиотеки со служебными именами;
- порядок компетенций на экране;
- правило статуса плана перенесено в домен.

После реализации код проверили четыре независимых направления: содержимое отчёта,
XLSX и сборка, Rust и ACL, контроллер и правила проекта. Каждую находку отдельно
проверяли два скептика.
- Подтверждено и исправлено:
  - даты с 01.01.1900 по 28.02.1900 уходили в Excel на день позже.
- Мнения разделились; исправлено:
  - тест «без Worker» не доказывал, что используется шим. Добавлены маркер шима и
    проверка alias в продакшн-конфиге Vite. Контрольные прогоны без alias и без
    `inline` теперь падают;
  - Excel терял цифры у чисел длиннее 15 значащих цифр.
- Отклонено скептиками, но учтено: в сообщениях Rust об ошибке записи было английское
  название вида ошибки. Теперь причина пишется по-русски.
- Остальные находки отклонены как недостижимые или соответствующие плану.

## Не проверено

- **macOS целиком:** сборка, NSSavePanel в виде листа, фильтр `.xlsx`, замена файла на
  APFS, запасная запись поверх файла, если macOS (TCC) не даст создать временный файл
  рядом, WKWebView.
- **Открытие файла в Excel для Windows и Mac** и внешний вид листов. На Mac PO ранее
  открыл файл, созданный по той же спецификации.
- Настоящая блокировка файла самим Excel: проверялась эквивалентная эксклюзивная
  блокировка из PowerShell.
- На Windows ошибка COM в окне сохранения выглядит как отмена: библиотека rfd не
  различает эти случаи.
- Пробный Windows ZIP из `src-tauri/target/portable/` собран **до** появления отчёта.
  ZIP с отчётом собран и проверен локально на этапе 3 (MACOS_BUILD.md); дальше ZIP
  собирает GitHub Actions.
