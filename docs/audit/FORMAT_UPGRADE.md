# Обновление формата проекта: проверка совместимости

Дата: 2026-10-06. Этап 1 технического плана (../architecture/QUARTER_PLANNING_PLAN.md),
решение DEC-044. Ветка `quarter-planner`, сборка не выпущена.

## Что проверяется

Проект, сохранённый версиями 0.1.0–0.3.0 (схема файла 1, снимки версии 1):

1. открывается новой версией без изменения файла и с теми же числами;
2. при первом сохранении — вопрос; отмена ничего не пишет;
3. после подтверждения сначала создаётся резервная копия, побайтно равная исходному файлу;
4. затем файл переходит на схему 2, сохранённый квартал — на снимок версии 2, остальные
   кварталы не переписываются;
5. версия 0.3.0 отказывается открыть обновлённый файл и не меняет его;
6. копия, поставленная на место `capacity.sqlite`, снова открывается версией 0.3.0 с
   прежними числами.

Реальные проекты и выгрузки PO не использовались.

## Как запускалось

- Новая сборка: `npm run tauri build` из ветки `quarter-planner`, `src-tauri/target/release/capacity-planner.exe`.
- Версия 0.3.0: тот же файл, собранный 2026-09-27 перед выпуском, сохранён в
  `src-tauri/target/compat-0.3.0/` до сборки новой версии; ProductVersion 0.3.0.
- Каждый EXE — с отдельным профилем WebView2 (`WEBVIEW2_USER_DATA_FOLDER`) и портом отладки
  (`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=…`), затем
  `node --experimental-websocket scripts/format-upgrade-smoke.mjs upgrade|legacy …`.
- Системное окно выбора папки подменено в странице (как в `portable-reopen-smoke`);
  открытие проекта, SQL, расчёт и обновление формата — настоящие.

С 0.4.0-rc.2 (Q-001, DEC-055) окно не может подменить выбор папки: `project_open` и
`project_create` принимают только папку, выбранную в системном окне, которое показывает Rust.
Сценарии выбирают папку в настоящем окне (`scripts/native-folder-dialog.mjs`, Windows);
подмена осталась только для EXE 0.3.0 в режиме `legacy`.

проектам в обоих режимах.

| `workflow-smoke-1790417397644` | `3cb5e98dfc7f…` | `e60aec9b5ea3…` | «Версия проекта не поддерживается» |

**Новая сборка, для каждого проекта:**
- Открытие и закрытие копии не меняют файл: SHA-256 совпадает.
- Числа 4 квартала 2026 те же, что считала 0.3.0:
  - «Продукт»: 50,40 ч, 30 ч, 20,40 ч;
  - «Встречи и резерв»: 201,60 ч, 25 ч, 176,60 ч.
- Все строки кварталов — снимки версии 1.
- Изменение оценки (30 → 28 ч) и «Сохранить квартал»:
  - появляется окно «Обновить формат проекта» с текстом PO и папкой проекта, статус «Ожидает решения»;
  - «Отмена» — файл не изменился, копии нет, изменения не сохранены.
- Повторное сохранение и «Обновить формат и сохранить»:
  - сообщение называет копию `capacity-backup-format1-2026-10-06.sqlite` в папке проекта;
  - копия побайтно совпадает с исходным файлом;
  - файл — схема 2;
  - 4 квартал — снимок версии 2, ревизия +1, все задачи «в плане», ни одно направление не стало резервом;
  - остальные кварталы остались снимками версии 1 с прежней ревизией;
  - «Продукт»: 28 ч, 22,40 ч.
- После повторного открытия правка на месте; файл и копия не изменились.

**Версия 0.3.0, для каждого проекта:**
- Обновлённая копия не открывается: «Версия проекта не поддерживается», файл не изменился.
- Копия, поставленная на место `capacity.sqlite` в новой папке, открывается с прежними
  числами (30 ч, 20,40 ч).

**Прежние возможности:** `scripts/report-export-smoke.mjs` на новой сборке прошёл дважды:
- создание проекта и квартала, сохранение, повторное открытие;
- выгрузка через настоящее окно «Сохранить как», перезапись, занятый файл, большой отчёт.

**Rust-тесты на временных проектах:**
- открытие файла схемы 1 не меняет его побайтно;
- ошибка копии — файл не меняется, временный файл удалён;
- сбой транзакции — откат, копия остаётся;
- завершение процесса внутри транзакции — после открытия исправная схема 1, обновление можно повторить;
- восстановление из копии;
- схемы 3 и 999 отклоняются без изменений папки.

## Что не проверено

- Mac: сборка и тесты на macOS не запускались (push не выполнялся, GitHub Actions не
  запускались); на Mac PO не проверялось.
- `webview-smoke` и `portable-reopen-smoke` в этом этапе не запускались; они читают данные
  в старом виде и будут прогнаны перед промежуточной сборкой.
- Системное окно выбора папки в этих прогонах подменено.
- Сбой диска во время копии и обрыв питания на реальном EXE не имитировались; эти случаи
  покрыты Rust-тестами на временных проектах (ошибка копии, сбой транзакции, завершение
  процесса внутри транзакции).
