# Kaiten API: исследование для будущего импорта работ

Направление и правила — DEC-051 (../product/REQUIREMENTS.md). Это исследование, не решение и не начало
интеграции: реальные данные не подключались.

Для импорта только на чтение подходит публичный REST API Kaiten: GET-запросы с личным Bearer-токеном.
Токен действует с правами пользователя, а областей доступа и токенов «только чтение» в документации нет,
поэтому запрет записи должно обеспечить наше приложение. Поля «оценка в часах» в публичном API не нашли:
`size` — число без единиц (часы, story points или S/M/L), числовые пользовательские поля тоже без единиц.
Поэтому поле с оценкой и его единицы выбирает пользователь. У коробочной версии (on-premise) API тоже есть,
но её адрес, версию и сертификаты можно проверить только в компании.

Проверено 2026-10-07 только по публичным страницам. Мы не входили ни в один экземпляр Kaiten и не вызывали
его API; работа в установке компании PO не проверялась. Метки: **Д** — подтверждено документацией;
**П** — предположение / нужно проверить. Номера в скобках — источники в конце.

## 1. Доступ к API

- Облако: `https://<домен>.kaiten.ru/api/v1`; псевдоним последней версии — `/api/latest`;
  «JSON API version: 1»; HTTPS, `application/json` — **Д** [1].
- Облако из корпоративной сети: FAQ просит открыть `<домен>.kaiten.ru`, `files.kaiten.ru`, `api.kaiten.ru`,
  `kaiten.ru`, `wss://socket.kaiten.ru` — **Д** [12]. Для импорта, вероятно, хватит `<домен>.kaiten.ru` — **П**.
- On-premise: тариф «Корпорация», установка через Docker Compose/Kubernetes, «Открытый API» в изолированной
  среде без обращения к серверам Kaiten — **Д** [10][11]. Официальный CLI работает «с API Kaiten — облачным
  или локальным» — **Д** [13].
- Адрес API on-premise: в документации только `*.kaiten.ru`; вероятно, `https://<корпоративный-домен>/api/latest`.
  Версия может отставать от облака, изменения с 2026-10-01 там могут вести себя иначе — **П**.
- Тарифы: в таблице FAQ API отмечен на всех тарифах, включая «Бесплатный» — **Д** [11]. На форуме пишут,
  что в режиме «Lite» API нет; страница не открылась (HTTP 429) — **П** [20].
- Лимит: «50 requests per second», заголовки `X-RateLimit-Remaining` и `X-RateLimit-Reset`, при превышении
  код 429 — **Д** [1]. Лимит on-premise не описан — **П**.
- Пагинация `GET /cards`: `limit` (по умолчанию и максимум 100) и `offset`; при `version=2` (поиск OpenSearch) —
  курсор `start_position` — **Д** [2]. С 2026-10-01 и другие списки (пространства, списания времени) отдают
  не больше 100 записей и заголовок `X-Pagination-Limit` — **Д** [5][6]. С 2026-11-01
  `GET /spaces/{id}/boards/{id}` не возвращает карточки; вместо него `GET /cards?board_id=…` — **Д** [4].
- Сертификаты, VPN, прокси для on-premise: публичных требований нет — **П**. Вероятно, приложению нужно
  доверять системному хранилищу сертификатов (корпоративный CA); про прокси станет ясно после ответов PO.
- Для нас: сейчас приложение не ходит в сеть (REQ-002, DEC-023). Импорт добавит исходящие запросы по явному
  действию пользователя. Нужны отдельное решение PO по правилам DEC-048 и обновление `docs/audit/NETWORK_CHECK.md`.

## 2. Авторизация

- Каждый запрос несёт `Authorization: Bearer <token>` — **Д** [1]. Токен создаётся в разделе «API-ключ»
  настроек профиля: `https://<домен>.kaiten.ru/profile/api-key` — **Д** [1][14]. Шагов в FAQ нет,
  только заголовок раздела.
- Токен действует от имени пользователя: API отдаёт то, что «available to the current user» — **Д** [5].
  Областей (scopes) и токенов только для чтения в документации не нашли. Значит, токен разрешает и запись,
  а ограничение «только чтение» обеспечивает наше приложение.
- Срок жизни, отзыв и число ключей на пользователя публично не описаны — **П**. Неверный токен даёт 401
  «Invalid token» — **Д** [2].
- OAuth или SSO для API в документации нет. Сторонний клиент пишет, что «OAuth не поддерживается» — **П** [19].
  SSO в тарифах относится ко входу в интерфейс, не к API — **П** [11].
- Предложение по хранению токена: системное хранилище ОС (Windows Credential Manager, macOS Keychain);
  никогда не класть в `capacity.sqlite`, папку проекта, XLSX, логи и тексты ошибок; запросы только из Rust
  по списку разрешённых GET-путей, WebView токен не получает; маскированный ввод и кнопка «Забыть токен».
  Работу Keychain со сборкой с ad-hoc подписью (без Developer ID) можно проверить только на Mac — **П**.

## 3. Поля карточки

- Нужные нам поля карточки — **Д** [2][3]:
  - `id` (integer), `uid`, `title`, `board_id`, `column_id`, `lane_id`, `type_id` и `type.name`;
  - `state`: 1 — в очереди, 2 — в работе, 3 — готово; `condition`: 1 — на доске, 2 — в архиве; флаг `archived`;
  - `created`, `updated`, `version`, `external_id`, `path_data` (пространство, доска, колонка, дорожка);
  - `properties` в виде `id_{propertyId}: значение`; `planned_start`/`planned_end` — даты таймлайна, не оценка;
  - `tags` и `external_links` в полной карточке; метки также через `GET /cards/{id}/tags`.
- Ссылка на карточку: пример из FAQ — `https://домен.kaiten.ru/board/123/card/456` — **Д** [15]. Её можно
  собрать из `board_id` и `id`, но карточка может переехать на другую доску. Поэтому ключ — `id`, а ссылка
  нужна для удобства — **П**. Короткие ссылки по пользовательским ключам есть только в on-premise — **Д** [16].

| Поле API | Тип / что хранит | Единицы | Использовать как часы? |
|---|---|---|---|
| `size` | number \| null, «Numerical part of size» | не заданы (часы, SP, рубли — по договорённости) [17] | только если пользователь явно указал, что у команды размер в часах |
| `size_unit` | string, «Text part of size» | произвольный текст | нет, только показать |
| `size_text` | string: `'1'`, `'.5'`, `'S'`, `'3 M'`, `'XL'` | произвольные | нет; буквенные размеры никогда не переводить в часы |
| `properties.id_N`, тип `number` | число [7] | у поля есть только название | только поле, которое пользователь выбрал и подтвердил как «часы» |
| `collective_score` (`values_type` number/text) | коллективная оценка: мин., макс., медиана, среднее [7][18] | не заданы | по умолчанию нет |
| `formula` | вычисляемое поле [7] | не заданы | **П**, не использовать до проверки |
| `estimate_workload` | number, описание только «Estimate_workload» [2] | не описаны | **П**, не использовать |
| «Трудозатраты» (модуль «Гант и ресурсное планирование») | часы ресурса за период [21] | часы | **П**: публичного эндпоинта не нашли |
| `time_spent_sum`, `time-logs.time_spent` | фактически списанное время [2][6][22] | минуты | нет: это факт, не оценка |
| `children_number_properties_sum.size` | сумма размеров дочерних карточек | как у `size` | нет |

## 4. Отбор карточек для импорта

- Фильтры `GET /cards` — **Д** [2]:
  - расположение: `space_id`, `board_id`, `column_id`/`column_ids`, `lane_id`;
  - вид и состояние: `type_id`/`type_ids`, `tag`/`tag_ids`, `states`, `condition`, `archived`;
  - даты: `created_*`, `updated_after`/`updated_before`, `last_moved_to_done_at_*`;
  - текст `query` (по умолчанию по названию, см. `search_fields`), `exclude_*`, `order_by`,
    составной `filter` (BETA, base64).
- Справочники для экрана выбора — **Д** [5][7][8][9]: `GET /spaces`, `GET /spaces/{id}/boards` (с колонками и
  дорожками), `GET /tags`, `GET /card-types`, `GET /company/custom-properties`.
- Сценарий: пространство → доска → по желанию колонки, метки и типы; по умолчанию `condition=1`. Страницы по 100
  запрашиваются последовательно, при 429 ждать до `X-RateLimit-Reset`. Для 1–3 команд это, вероятно,
  десятки запросов — **П**.

## 5. Безопасное обновление (предложение)

- Только чтение: никаких POST/PATCH/DELETE, вебхуков и фоновой синхронизации; импорт запускает пользователь.
- Работа хранит адрес экземпляра, `id` карточки и ссылку. Дубликат определяется по паре «экземпляр + id»,
  в том числе для ссылки, которую пользователь вставил вручную.
- Повторный импорт показывает различия: новая карточка, изменилось название, изменилась внешняя оценка,
  карточка исчезла из выборки или ушла в архив. Каждое обновление подтверждается отдельно (или «отметить все»).
- Подтверждённая локальная оценка не перезаписывается. Новая внешняя оценка видна рядом («в Kaiten: N ч»)
  и принимается только явным действием; `null` остаётся `null`, а не 0.
- Внешний статус («готово», архив) только показывается. Отметку планирования и бюджет квартала он не меняет.
- Ничего не удаляется. Исчезнувшая карточка получает пометку «не найдена в Kaiten».
- У оценки хранится её происхождение: поле Kaiten, единица, дата импорта, решение пользователя.

## Что нужно узнать у PO

1. Облако или on-premise; точный адрес; для on-premise — версия и контакт администратора.
2. Как команда записывает оценку: «Размер» (в каких единицах), числовое пользовательское поле (название),
   коллективная оценка, «Трудозатраты» в Ганте или нигде. Нужен пример без реальных данных.
3. Из каких пространств, досок, колонок, типов и меток брать работы на квартал.
4. Разрешены ли личные API-токены для настольного инструмента; есть ли у них срок жизни; нужен ли служебный
   пользователь только с правом чтения.
5. Сеть: VPN, прокси, корпоративный CA или самоподписанный сертификат, белые списки адресов.
6. Нужно ли согласование ИБ: передача и хранение токена (Keychain/Credential Manager), исходящие запросы.
7. Нужны ли архивные и дочерние карточки (эпики, подзадачи) или только карточки верхнего уровня.
