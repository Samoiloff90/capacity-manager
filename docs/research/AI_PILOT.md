# ИИ-пилот: «корпоративный Copilot», MCP или вызов API из приложения

Дата: 2026-10-07. Статус: исследование по публичной документации, не решение. В текущую версию
интеграции не входят (DEC-048); сценарии и границы безопасности — DEC-052; среда PO не проверялась, вход в сервисы не выполнялся.
Метки: **[Д]** — подтверждено документацией (ссылка в «Источниках»); **[П]** — предположение / нужно проверить.

## Кратко

- «Корпоративный Copilot» — это может быть один из 6–8 разных продуктов с разными API и разной
  поддержкой MCP. Пока не известны продукт, вендор и место работы модели, выбирать архитектуру нельзя.
- Облачные ассистенты (Copilot Studio, агенты Microsoft 365 Copilot, MCP Hub Yandex) подключают
  только **удалённый** MCP-сервер по URL **[Д]**. Для Capacity Planner это означает сервер или туннель
  и противоречит local-first. Локальный stdio-сервер доступен только клиенту на том же компьютере, например IDE.
- Для пилота «объяснить план / черновик письма» лучше подходит вариант B: приложение само отправляет
  минимальный контекст, который пользователь видел перед отправкой, в разрешённый API, а числа в ответе вставляет и сверяет само. Это вывод анализа, не факт.

## 1. Что может скрываться за «корпоративным Copilot»

## 2. Два направления

### A. Ассистент читает данные Capacity Planner через MCP

Capacity Planner предоставляет MCP-сервер с 2–3 инструментами только для чтения: одного выбранного плана
или источника.

- **Транспорт решает всё.** Для stdio клиент сам запускает сервер подпроцессом **[Д]**, поэтому этот
  вариант работает только с клиентом на том же компьютере (IDE, desktop-ассистент). Облачный ассистент
  (Copilot Studio, агенты M365, MCP Hub) ходит на удалённый HTTPS URL **[Д]**. Значит, нужен сервер,
  туннель или шлюз (APIM, on-prem data gateway **[П]**) — постоянно доступный компонент вне приложения.
  Это противоречит REQ-002, DEC-023 и DEC-048.
- **Локальный HTTP не спасает.** Сервер обязан проверять `Origin`; рекомендуется слушать только
  127.0.0.1 и требовать аутентификацию из-за DNS rebinding **[Д]**. Облачный клиент до localhost всё равно не достанет.
- **Архитектурная сложность [П].** «Выбранный план» существует только в окне приложения, а stdio-сервер
  запускается клиентом отдельно. Формулы находятся в TypeScript (`src/domain/capacity/`), а в Rust их
  переносить нельзя. Серверу нужен либо канал связи с запущенным приложением, либо снимок результатов
  расчёта, который пользователь выгрузил явно.
- **Безопасность MCP (спецификация 2026-07-28) [Д]:** для HTTP — OAuth 2.1, токены с проверкой
  получателя (RFC 8707), передавать токены дальше (token passthrough) запрещено; для stdio учётные данные берутся
  из окружения. Confused deputy возникает у MCP-прокси со статическим client ID — нужно согласие на
  каждого клиента. Локальный сервер — это код с правами пользователя, и клиент должен показать команду
  запуска. По инструментам: человек должен иметь возможность отклонить вызов; сервер **обязан** проверять входные данные, права, частоту вызовов и очищать
  результаты; клиент должен показывать входные данные инструмента; аннотации вроде `readOnlyHint` недоверенные.
- **Prompt injection через результаты инструментов.** Названия работ попадают в контекст чужой модели.
  Приложение не управляет ни инструкцией модели, ни самой моделью, ни журналами ассистента, ни тем, с какими ещё инструментами
  ассистент смешает данные **[П]**.
- **Предпосылки:** клиент поддерживает нужный транспорт; политика организации разрешает сервер
  (у GitHub по умолчанию выключено **[Д]**); ИБ согласовала модель и журналы клиента.
- **Объём:** stdio — **M–L** (отдельный режим или исполняемый файл, чтение проекта без записи, связь с
  окном, доставка и подпись на обеих ОС). Удалённый сервер — **L** с эксплуатацией.
- **Риски:** данные уходят туда, куда их направит ассистент; среду PO нельзя проверить без доступа;
  клиенты и спецификация MCP быстро меняются (SSE уже вышел из употребления).

### B. Приложение само вызывает разрешённый ИИ-сервис

- **Что строим [П]:** чистый TS-модуль `src/ai/`: сборка контекста из результатов расчёта, предпросмотр,
  проверка чисел, тесты Vitest. Узкая Rust-команда отправляет POST на один настроенный адрес, по образцу
  `report_export.rs`; фронтенду не выдаются права `http:*`. Токен хранится в связке ключей ОС (crate `keyring`:
  Keychain на macOS, Credential Manager на Windows **[Д]**), не в проекте и не в журналах (DEC-048).
- **Поток данных:** расчёт → сборщик минимального контекста → окно «Что будет отправлено» → кнопка
  «Отправить» → один запрос → ответ → проверка чисел → черновик (копировать / закрыть). Без автоповтора и
  без перехода на другую модель.
- **Предпосылки:** адрес API, схема авторизации, совместимость с OpenAI или протокол вендора,
  сертификаты (для GigaChat — НУЦ Минцифры **[Д]**), прокси, разрешённый класс данных, хранение
  запросов (у Yandex заголовок отключения логов **[Д]**; у Azure — abuse monitoring **[Д]**).
- **Объём:** **M** для одного OpenAI-совместимого провайдера; **+S** на нестандартного (токен на 30 мин,
  свой сертификат). Нужно обновить `docs/audit/NETWORK_CHECK.md`: впервые появится исходящий трафик с данными.
- **Риски:** ответ модели неточен (снижается проверкой чисел и режимом черновика); утечка через журналы вендора;
  хранение токена на Mac не проверено **[П]**; это первое исключение из REQ-002, нужно решение PO.

### Сравнение и правило выбора

| | A: stdio MCP | A: удалённый MCP | B: вызов API |
|---|---|---|---|
| Нужен сервер | нет | да | нет (сервис компании) |
| Кто решает, что отправить | ассистент в рамках инструментов | ассистент | приложение и пользователь |
| Предпросмотр точного содержимого | зависит от клиента | зависит от клиента | да |
| Проверка чисел приложением | нет | нет | да |
| Подходит облачному Copilot | нет | да | только если есть API |
| Объём | M–L | L + эксплуатация | M |

- **A (stdio)** — если ассистент работает локальным клиентом с поддержкой stdio MCP, организация разрешает
  этот сервер, а ИБ согласовала модель и журналы клиента.
- **A (удалённый)** — только если в компании уже есть согласованный MCP-шлюз и PO отдельно решит
  отступить от local-first для этой функции.
- **B** — если есть разрешённый API (OpenAI-совместимый или вендорский) и ИБ допускает класс данных.
- Если Copilot только облачный и API нет, пилот откладывается. Вариант без сети: приложение
  собирает тот же текст, пользователь сам копирует его в корпоративный чат. Класс данных всё равно нужно согласовать.

## 3. Минимальный пилот: «объяснить план» и «черновик письма заказчику»

**Отправляется** только для выбранного квартала и одного источника. Поля берутся из `SourceState`
(`src/domain/capacity/source-plan.ts`), формулировки «не менее / не более» — из `describeRest`:

```json
{ "квартал": "2027 Q1", "источник": "Платформа (пример)", "квота_ч": "250", "доля_задана": true,
  "запланировано_ч": "228", "работ_без_оценки": 1, "остаток_ч": "22", "перебор_ч": "0",
  "оговорка": "остаток не более 22 ч: есть работа без оценки",
  "работы": [ { "id": "w1", "название": "Выгрузка отчёта", "оценка_ч": "40" },
              { "id": "w2", "название": "Новый фильтр", "оценка_ч": null } ] }
```

**Не отправляется никогда:** ФИО и состав команды, ставки, отсутствия и их причины, календарь, другие
источники и кварталы, путь к проекту и файл БД, описания работ, токены. Телеметрии нет. Если компетенций
нет в данных, выводов о перегрузке QA или конкретных людей нет — это указано в инструкции и в предпросмотре.

**Предпросмотр:** окно показывает точный текст запроса (инструкцию и блок данных), адрес получателя и
модель. Работы можно исключить флажками. До нажатия «Отправить» в сеть ничего не уходит. При
недоступности сервиса — сообщение, приложение работает как прежде.

**Проверка чисел:**
1. Модель пишет текст с метками `{квота}`, `{остаток}`, `{w1.оценка}`; значения подставляет приложение
   своим форматтером. Модель ничего не вычисляет.
2. Перед показом приложение ищет в ответе числа без меток. Каждое сверяется с отправленными значениями;
   незнакомое число (сумма, процент, оценка работы `null`) подсвечивается, и черновик помечается как непроверенный.
3. Неизвестная оценка подставляется как «без оценки», и выдуманное значение ловит пункт 2.

**Нейтрализация injection** (OWASP LLM01 **[Д]**): названия работ передаются только в блоке данных, а не в инструкции, и
помечены как недоверенные. Из них убираются переводы строк и управляющие символы, длина ограничивается
(например, 200 символов). Модели не даются инструменты (function calling), поэтому инъекция не может
запустить действие. Ответ показывается как простой текст без HTML и Markdown, ссылки и картинки не
загружаются. Данные не меняются: любая будущая правка — только через предпросмотр и подтверждение руководителя.

## 4. Что нужно узнать у PO / ИБ

1. Точное название продукта и вендор «корпоративного Copilot»; ссылка на внутреннюю страницу или регламент.
2. Где работает модель (облако вендора, регион, частное облако, on-prem) и какие промежуточные сервисы участвуют.
3. Клиенты: веб, Teams, desktop, IDE. Есть ли у сотрудников локальный клиент с MCP.
4. Поддерживает ли он MCP: stdio или удалённый HTTP; кто разрешает серверы (allowlist, реестр, DLP).
5. Есть ли API для приложений: адрес, авторизация (ключ, OAuth/Entra, IAM), совместимость с OpenAI,
   сертификаты, прокси, лимиты.
6. Какой класс данных разрешено отправлять: названия работ, источники, часы; запрет на персональные данные.
7. Журналы и хранение запросов и ответов: срок, кто имеет доступ, можно ли отключить (как `x-data-logging-enabled`).
8. Используются ли данные для обучения; есть ли автоматический переход на внешнюю модель (должен быть выключен).
9. Порядок согласования: кто утверждает, нужна ли проверка сетевого трафика приложения.
10. Решение PO: допускается ли исключение из REQ-002 для явной отправки по кнопке.
